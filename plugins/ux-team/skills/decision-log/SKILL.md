# decision-log

기획 중에 정해진 결정을 결정 기록 한 건으로 만들어 중앙 컨텍스트에 남깁니다.
중앙 컨텍스트는 팀 결정 · 용어 · 상충의 정본입니다 (`references/_shared/crossings.md` 중앙 컨텍스트 행).
결정은 사람이 합니다. 이 스킬은 정해진 것을 받아 적기만 합니다.

## 어디서 되는가

- Chat · Cowork · Code 탭 모두 같습니다. ClickUp 커넥터만 씁니다.
- ClickUp 커넥터가 연결되어 있지 않으면 Customize › Connectors에서 연결하라고 안내합니다. 연결 없이도 복사할 글은 만들 수 있으므로, 복사할 글만 받을지 묻습니다.

## 하지 않는 것

- 확인 없이 남기지 않습니다 (ACC-37).
- 근거를 지어내지 않습니다. 없으면 "근거 미기재"로 둡니다 (ACC-38).
- 한 번 쓴 번호를 다시 쓰지 않습니다 (ACC-39).
- 결정 기록을 지우거나 고쳐 쓰지 않습니다. 바뀐 결정은 새 번호로 남기고 옛 기록에 대체 답글을 답니다. 지운 기록은 셀 수 없어 번호가 다시 쓰일 수 있기 때문입니다.
- 회의 내용 전체를 요약하지 않습니다. 정해진 결정만 받습니다.
- "확정"이라고 쓰지 않습니다.

## 진행 순서

### 1. 정해진 결정인지 보기

- "~하면 좋겠다", "~로 갈까" 같은 말이면 정해진 것인지 묻습니다. 아직이면 남기지 않습니다.
- 회의 요약을 부탁받으면 이 스킬이 맡지 않는다고 알리고, 그중 정해진 결정이 있으면 골라 달라고 합니다.

### 2. 입력 모으기

| 칸 | 없을 때 |
|---|---|
| 결정 | 묻습니다 |
| 누가 | 묻습니다. 정한 사람이나 자리(예: 10/13 팀 회의)를 적습니다 |
| 언제 | 묻습니다. "오늘" · "어제"는 날짜로 바꿉니다 |
| 근거 | 아래 "근거 가려내기"를 따릅니다 |
| 관련 태스크 | 링크를 받거나, 이름이면 `references/_shared/team-places.md`의 상위 태스크 리스트에서 찾아 후보를 보여 줍니다. 없으면 "없음" |
| 대체 | 앞선 결정을 바꾸는 것이면 그 번호. 사용자가 말하지 않으면 한 번 묻습니다 |

- 대화에 이미 나온 값은 다시 묻지 않습니다.
- 한 번에 여러 건이면 건마다 따로 모읍니다.

#### 근거 가려내기

근거는 "왜 이렇게 정했나"에 대한 답입니다.
사용자가 이 결정의 이유로 말한 것만 근거로 적습니다.

근거로 봅니다
- 사실 · 수치: 문의 12건, 개발 공수 3일
- 제약: BE가 지원하지 않음, 출시일이 고정됨
- 앞선 결정 · 정책: DEC-NN, 티키타 위키의 규칙
- 자료 링크: 회의록, 스레드, 문서
- 이유가 붙은 판단: "A가 B보다 단계가 하나 적어서"

근거로 보지 않습니다
- 누가 · 언제 · 어디서 정했는지: "10/13 회의에서", "CEO가 정함" → "누가" · "언제" 칸에 적습니다
- 결정을 다시 말한 것: "A로 하기로 해서"
- 이유 없는 선호: "그게 나아서", "그냥"

가리는 방법
- 근거가 분명하면 사용자의 말을 그대로 옮깁니다. 줄일 수는 있지만 덧붙이지 않습니다.
- 애매하면 해당 말을 인용하고 "이것을 근거로 적을까요?"라고 묻습니다.
  - 앞선 대화에서 찾은 말이 이 결정의 이유로 한 말인지 분명하지 않을 때도 여기에 해당합니다.
- 없으면 "왜 이렇게 정했는지 남길 근거가 있나요?"라고 한 번 묻습니다. 그래도 없으면 "근거 미기재"로 둡니다.

### 3. 남길 곳 정하기

- `references/_shared/team-places.md`의 ClickUp 표에서 "결정 기록" 행을 읽습니다.
- 값이 있으면 그곳에 남깁니다.
- 값이 `<미정>`이면 둘 중 고르게 합니다.
  - 결정 기록을 남길 태스크 링크를 줍니다 → 그 태스크 댓글에 남깁니다.
  - 링크를 주지 않습니다 → 복사할 글만 줍니다.
- 같은 대화에서 한 번 받은 링크는 다시 묻지 않습니다.

### 4. 번호 세기

- 남길 곳의 댓글과 답글을 끝까지 읽고, `DEC-NN` 가운데 가장 큰 번호에 1을 더합니다.
  - 개수가 아니라 최댓값입니다. 빈 번호가 있어도 그 번호를 다시 쓰지 않습니다.
  - 대체 답글에 나온 번호도 셉니다.
  - 아직 기록이 없으면 `DEC-01`부터 씁니다.
- 댓글을 끝까지 읽지 못하면 번호를 `DEC-??`로 두고 그 사실을 알립니다. 추측해서 붙이지 않습니다.
- 복사할 글만 주는 경우도 `DEC-??`로 둡니다.
- 여러 건이면 이어지는 번호를 차례로 붙입니다.

### 5. 초안 보여 주기

건마다 아래 양식을 그대로 채웁니다.

```
DEC-NN 결정 한 줄 요약
- 결정: …
- 누가: …
- 언제: YYYY-MM-DD
- 근거: … (없으면 "근거 미기재")
- 관련 태스크: 링크 (없으면 "없음")
- 대체: DEC-MM (앞선 결정을 바꿀 때만. 아니면 이 줄을 지웁니다)
```

- 대체가 있으면 옛 기록에 달 답글도 함께 보여 줍니다.

```
DEC-NN으로 대체 <새 기록 링크>
```

- 초안 위에 남길 곳(태스크 이름 · 링크)을 적고 "이대로 남길까요?"라고 묻습니다. 대체 답글도 같은 확인으로 받습니다.
- 근거가 "근거 미기재"이면 초안 위에 "근거 없이 남깁니다." 한 줄을 덧붙이고, 같은 확인으로 받습니다.
- 글은 `references/_shared/writing.md`를 따릅니다.

### 6. 확인받고 남기기

- 분명히 승인했을 때만 남깁니다. 고칠 점을 받으면 고쳐서 다시 묻습니다.
- 남기기 직전에 4단계를 한 번 더 합니다. 그사이 다른 사람이 남겨 번호가 바뀌었으면 새 번호로 고친 초안을 보여 주고 다시 확인받습니다.
- 결정 한 건을 댓글 한 개로 남깁니다.
- 대체가 있으면 새 기록을 먼저 남기고, 그 링크를 넣어 옛 기록에 답글을 답니다.
- 남긴 뒤 같은 번호가 둘 보이면 알리고, 나중 것의 번호를 고칠지 묻습니다. 스스로 고치지 않습니다.

### 7. 링크 주기

- 남긴 댓글 링크를 줍니다. 대체 답글을 달았으면 그 링크도 줍니다.
- 복사할 글만 준 경우: "붙여 넣을 곳의 마지막 번호 다음 번호로 `DEC-??`를 바꿔 주세요."라고 안내합니다.
