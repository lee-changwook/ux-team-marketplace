# Checklist

## 1. 승인 게이트 (Step 5) — write 전 필수

사용자에게 아래를 **한 화면에** 보여주고 확인받는다 (질문 도구가 있으면 그것으로). 사용자에게 보이는 글은 높임말로 쓴다.

### 1-1. 보여줄 것

```
■ 범례
  CHG 변경 · ANN 주석 · DSC Description 카드 · OVL 오버레이 (이 번호는 Figma 캔버스에 넣지 않습니다)

■ 대상
  base   : <프레임명> (<node-id>) — <w>×<h>
  파일   : <파일명> / page <페이지명>
  배치   : <섹션명> 안 (<x>, <y>)  ← 섹션 로컬 좌표
  신규   : [SECTION] <새 섹션 이름>

■ 변경목록
  CHG-01  추가  <앵커> → <node-id>   <내용>                     [A·B]
  CHG-02  수정  <앵커> → <node-id>   <내용>                     [A]
  CHG-03  추가  —                     시안 2 (<구분 기준>)        [B]

■ 폰트
  Pretendard 로드 <가능 | 불가 → 42dot Sans로 대체>
  대체 시 영향: 라벨을 바꾸는 <n>개 텍스트가 42dot Sans가 됩니다

■ 주석 계획 (설명 소스를 받았을 때만)
  ANN-01  Annotation  <앵커> → <node-id>   카테고리 `API`   출처: fetcher <이름>
  DSC-01  Description <섹션 오른쪽 (x, y)>                  출처: <문서> <절>
  OVL-01  오버레이    <대상 필드>                           커넥터 앵커용
  카테고리: <파일에서 읽은 것> / 같은 이름 중복 시 어느 쪽인지
  API 주석: <붙입니다 | 붙이지 않습니다 — 이유: 레포 없음 · 화면. 붙이려면 레포를 연 Code 탭에서 다시 실행해 주세요>

■ 원문 ↔ 코드 충돌 (있으면)
  <원문 문장> ↔ <코드·합의 사실>  → 원문은 그대로 두고 보고만 합니다

■ 미결
  Q1. <방향 텍스트만으로 정해지지 않은 것>
```

### 1-2. 물을 것

- 변경목록이 방향과 맞는가 (빠진 것 · 과한 것)
- 배치 위치가 맞는가
- 미결 답
- 폰트 대체를 감수하고 진행할지, 재시작 후 다시 할지
- write 실행 OK

### 1-3. 게이트 통과 조건

- [ ] Figma 커넥터 연결과 base 파일 읽기를 Step 0에서 확인했다
- [ ] (모드 B를 거쳤으면) 캡처 전 확인을 받았고, staging에서 조회 · 이동만 했다
- [ ] CHG-NN 모든 행에 **실제 node-id**가 박혀 있다 (정찰로 확인한 것. 추측 금지)
- [ ] `추가` 행마다 **clone source**가 지정돼 있다
- [ ] 방향 텍스트에 없는 항목이 목록에 없다
- [ ] 타겟이 다른 파일이면 clone 제약을 고지했다
- [ ] 폰트 상태를 숨기지 않았다
- [ ] (설명 소스가 있으면) 주석 계획 표가 있고, 카테고리를 **파일에서 읽어** 골랐다. 같은 이름이 둘이면 사용자에게 물었다
- [ ] 기획 원문과 코드의 충돌을 찾아 보고했다 (고치지 않았다)

## 2. 최종 검증 (Step 9)

### 2-1. 구조

- [ ] `hifi` clone본이 **원본과 나란히** 있고 원본은 그대로다 (원본 node-id로 노드 구조를 다시 읽어 확인)
- [ ] 패치가 전부 clone본 안에 적용됐다 (원본에 섞이지 않았다)
- [ ] 생성한 노드가 기존 작업물과 **겹치지 않는다**
- [ ] 화살표가 `VECTOR`이고 이름이 `<출발> --> <도착>` 형식이다
- [ ] 시안 섹션 구조가 `라벨 스트립 → 시안 프레임 → 화살표 → 메모` 순이다

### 2-2. 시각 (`screenshot`으로 눈으로)

- [ ] **라벨이 잘리지 않았다** — 텍스트를 바꾼 컨테이너마다 `HUG` 적용 확인. 가장 자주 나는 실수다
- [ ] 메모 박스 안 한글이 폭 안에서 흐른다 (한 줄로 뚫고 나가지 않는다)
- [ ] 복제한 요소의 색·라운드·폰트가 주변과 같다 (변수 바인딩이 따라왔는지)
- [ ] 화살표 끝에 화살촉이 있고 출발·도착이 의도한 프레임을 가리킨다
- [ ] 시안 프레임이 설명에 필요한 범위만 담고 있다 (화면 전체가 다시 들어가지 않았다)
- [ ] (모드 B 직후) 오토레이아웃 자식 합이 부모 콘텐츠 폭을 넘지 않는다 — 넘으면 padding이 깨져 보인다. `FIGMA_RULES.md` 6-5절

### 2-3. 설명 레이어 (산출물 C를 만들었을 때)

- [ ] 주석이 **실제로 붙었는지 별도 호출로 확인**했다 (롤백 여부는 이것으로만 안다)
- [ ] 오버레이에 `layoutPositioning = 'ABSOLUTE'`가 걸려 있고, 넣은 뒤 화면이 밀리지 않았다
- [ ] Description 카드 스타일이 관행 프레임과 같다 — 배경·테두리(변수 바인딩)·radius·padding·lineHeight
- [ ] 원문에서 구조를 편 부분(표 → 평문)을 보고에 적었다
- [ ] 값 필드가 없어 주석 대상에서 제외한 노드를 보고했다

### 2-4. 보고

높임말로, 판단할 것 → 확인할 것 → 참고 순서로 쓴다. 맨 앞에 쓰는 ID의 범례를 둔다.

판단할 것
- [ ] 남은 미결
- [ ] 기획 원문과 코드의 충돌 (원문은 고치지 않았음)

확인할 것
- [ ] 커넥터로 이을 대상 쌍 목록 (수기로 남긴 작업)
- [ ] **주석은 Dev Mode(`Shift+D`)에서만 보인다**는 안내 — 처음 받는 사람은 반드시 막힌다
- [ ] 폰트 대체를 썼으면 그 사실과 영향 범위
- [ ] API 주석을 뺐으면 그 이유와 붙이는 방법
- [ ] 원문에서 구조를 편 부분 (표 → 평문)
- [ ] 실패·중단이 있었으면 잔재 노드 id와 정리 여부 (자동 삭제하지 않았음을 명시)

참고
- [ ] 생성 노드 URL (`https://www.figma.com/design/<fileKey>/?node-id=<id>`)
- [ ] CHG-NN별 반영 여부. 미반영 건은 사유

## 3. 사고 회피 (빨간 줄)

- **원본 노드 직접 수정** — 언제나 clone 위에서. 원본 작성자의 작업물은 자기 것이든 동료 것이든 read-only로 취급한다
- **색·폰트 하드코딩** — 복제로 해결되는 것을 손으로 재현하지 않는다
- **승인 없이 write** — 남의 파일에 대한 mutation이다
- **폰트 대체 무단 진행** — 사용자에게 알리고 선택을 받는다
- **자동 정리 범위 초과** — 자기가 붙인 prefix 노드만 지운다
