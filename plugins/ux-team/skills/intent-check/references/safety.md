# 쓰기 동작 차단

staging은 팀이 함께 쓰는 시험 데이터라, 쓰기 동작 하나가 다른 사람의 시험을 깨뜨립니다.
그래서 아래 네 겹을 모두 지킵니다.
앞의 것이 실패해도 뒤의 것이 잡게 둡니다.

## 1. 계획에서 빼기

- 쓰기가 필요한 확인 단위는 확인 계획에서 처음부터 "확인 못 함 (쓰기 필요)"로 둡니다.
- 사람이 계획을 승인하는 단계에서 이 목록을 봅니다.

## 2. 허용 동작

이것만 합니다.

- 주소 열기, 링크 · 메뉴 · 탭 이동, 뒤로 가기
- 스크롤, 마우스 올리기
- 조회 조건: 검색어 입력, 필터 · 기간 고르기, 조회 버튼, 정렬 머리글 누르기
- 드롭다운 · 모달 · 패널 열기
- 모달 · 패널 닫기: X 버튼과 Esc만

## 3. 누르지 않는 것

- 라벨에 이런 말이 든 버튼
  - 저장 · 등록 · 추가 · 수정 · 변경 · 적용 · 완료
  - 삭제 · 제거 · 해지 · 연결
  - 발송 · 보내기 · 전송 · 예약
  - 결제 · 수납 · 납입 · 환불 · 승인
  - 업로드 · 내보내기 · 다운로드
- 모달 안의 "확인" 버튼
- "취소"가 든 버튼: 창 닫기인지 결제 · 발송 취소인지 라벨로 가를 수 없습니다
- 체크박스 · 토글 · 별(즐겨찾기) · 드래그로 순서 바꾸기 · 표 안 셀 편집: 서버에 저장되는 경우가 있습니다
- 조회 조건이 아닌 입력란에 입력하거나, 그 입력란에서 Enter를 누르기
- 경고창(alert · confirm)을 띄울 수 있는 버튼: 브라우저 조작이 멈춥니다
- 비밀번호 입력란: 아무것도 입력하지 않습니다

무엇이 일어날지 모르는 버튼은 누르지 않습니다.
그 단위는 "확인 못 함 (쓰기 가능성)"으로 둡니다.

## 4. 감지하면 멈추기 (Code 탭)

- 클릭이나 조회 뒤마다 브라우저 도구로 네트워크 요청을 봅니다.
- GET이 아닌 요청(POST · PUT · PATCH · DELETE)이 생기면 그 자리에서 멈춥니다.
- 사용자에게 알립니다: 무엇을 눌렀는지, 어떤 주소로 어떤 요청이 나갔는지.
- 계속할지는 사용자가 정합니다. 조회에 POST를 쓰는 API도 있어 오탐일 수 있지만, 판정하지 않고 멈춥니다.
- 이미 나간 요청은 되돌리지 못합니다. 주 장치는 1~3입니다.

## 5. 결과에 남기기

- 출력 요약에 쓰기 동작 건수와, 감지로 멈춘 적이 있는지를 적습니다.
- 멈춘 적이 있으면 그 내용을 "판단할 것" 맨 위에 둡니다.
