# hello-ux-team

UX팀 플러그인을 처음 켰을 때, 그리고 리드가 Slack으로 팀 지침 갱신을 알렸을 때 사용자가 직접 부르는 스킬이다.
팀 지침을 설치하거나(Code 탭) 붙여 넣을 글을 주고(Chat · Cowork), 커넥터 연결을 점검하고, 스킬 목록과 하네스 안내 문서 링크를 준다.

## 어디서 되는가

| 단계          | Chat                | Cowork              | Code 탭                                       |
| ------------- | ------------------- | ------------------- | --------------------------------------------- |
| 1 화면 판별   | 됨                  | 됨                  | 됨                                            |
| 2 팀 지침     | 붙여 넣을 글을 준다 | 붙여 넣을 글을 준다 | `~/.claude/rules/ux-team-guide.md`에 설치한다 |
| 3 커넥터 점검 | 됨                  | 됨                  | 됨                                            |
| 4 안내        | 됨                  | 됨                  | 됨                                            |

- Chat · Cowork는 사용자 컴퓨터의 `~/.claude/`에 쓸 수 없다. 설치 대신 붙여 넣을 글을 준다.
- 설치 스크립트 `scripts/install-guide.sh`는 Code 탭에서만 돌린다.

## 하지 않는 것

- `~/.claude/rules/ux-team-guide.md` 밖의 파일을 만들거나 고치지 않는다. 개인 `~/.claude/CLAUDE.md`, 설정 파일, 백업 · 임시 파일이 모두 해당한다.
- 팀 지침 본문을 고치거나 요약하거나 기억으로 다시 쓰지 않는다. 언제나 `references/_shared/ux-team-guide.md`를 그대로 쓴다.
- 설정 화면이나 커넥터 화면을 직접 조작하지 않는다. 어디서 하는지 알려 주기만 한다.
- 커넥터 도구를 호출하지 않는다. 로그인 · 인증 도구도 부르지 않는다. 연결 여부만 본다.

## 1. 화면 판별

`references/_shared/surfaces.md`의 "판별"을 따른다.

- 셸 명령을 실행할 수 있고 `~/.claude` 폴더가 보이면 Code 탭 후보다. 2-A의 `check`를 돌린다.
  - `check`가 `NOT_MAC`을 내면 Code 탭이 아니다. Cowork 격리 환경에도 `~/.claude`가 있을 수 있다. 2-B로 간다.
- 그 밖에는 Chat 또는 Cowork다. 둘은 하는 일이 같아서 더 가르지 않는다. 2-B로 간다.
- 판별이 애매하면 지금 화면이 Chat · Cowork · Code 탭 중 무엇인지 사용자에게 묻는다.

## 2-A. 팀 지침 설치 (Code 탭)

먼저 상태를 본다.

```sh
sh ${CLAUDE_SKILL_DIR}/scripts/install-guide.sh check
```

| `check` 결과 | 할 일                                                                                    |
| ------------ | ---------------------------------------------------------------------------------------- |
| `NEW`        | 묻지 않고 `apply`를 돌린다. 사용자가 이 스킬을 부른 것이 설치 요청이고, 잃는 내용이 없다 |
| `SAME`       | 아무것도 쓰지 않는다                                                                     |
| `DIFF`       | 바뀌는 내용을 보여 주고 덮어쓸지 묻는다. 승인을 받은 뒤에만 `apply`를 돌린다             |
| `LINK`       | 덮어쓰지 않고 멈춘다                                                                     |
| `NOT_MAC`    | Code 탭이 아니다. 2-B로 간다                                                             |

```sh
sh ${CLAUDE_SKILL_DIR}/scripts/install-guide.sh apply
```

- 대상 경로 인자는 시험용이다. 실제 실행에서는 주지 않는다.
- `apply`가 오류를 내면(권한, 샌드박스 쓰기 제한 등) 설치 단계만 멈춘다. 다른 위치에 쓰거나 다른 명령으로 우회하지 않는다.
  - 결과 맨 위에 "팀 지침 설치 못 함"을 두고, 오류 문구와 해결 방법을 알린다.
  - 3 커넥터 점검과 4 안내는 이어서 한다. 조용히 건너뛰지 않는다.

`DIFF`일 때 보여 주는 법

1. 바뀌는 절을 한두 줄로 먼저 요약한다. 예: "'결정은 사람이 한다' 절에 한 줄이 더해집니다."
2. `check`가 낸 diff를 `diff` 코드 블록으로 그대로 붙인다.
3. `-` 줄은 덮어쓰면 사라진다고 알린다. 사용자가 직접 고친 줄이면 개인 규칙은 `~/.claude/CLAUDE.md`에 두라고 안내한다.
4. "덮어쓸까요?"라고 묻는다.

결과 문구

| 경우                 | 문구                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `NEW` → 설치         | 팀 지침을 `~/.claude/rules/ux-team-guide.md`에 설치했습니다. 새 세션부터 적용됩니다.                                                                         |
| `SAME`               | 팀 지침이 이미 최신입니다. 바꾼 파일은 없습니다.                                                                                                             |
| `DIFF` → 승인 → 설치 | 팀 지침을 새 내용으로 덮어썼습니다. 새 세션부터 적용됩니다.                                                                                                  |
| `DIFF` → 거절        | 덮어쓰지 않았습니다. 설치된 팀 지침은 그대로입니다.                                                                                                          |
| `LINK`               | `~/.claude/rules/ux-team-guide.md`가 다른 파일을 가리키는 링크라서 덮어쓰지 않았습니다. 링크를 정리한 뒤 다시 실행해 주세요.                                 |
| `apply` 실패         | **팀 지침 설치 못 함.** `~/.claude/rules/`에 쓰지 못했습니다: `<오류 문구>`. 쓰기 권한이나 샌드박스 쓰기 제한을 푼 뒤 `/hello-ux-team`을 다시 실행해 주세요. |

규칙 파일은 세션을 열 때 읽힌다. 그래서 설치한 세션에는 바로 적용되지 않는다.

## 2-B. 붙여 넣을 글 (Chat · Cowork)

`references/_shared/ux-team-guide.md`를 읽는다.
읽지 못하면(Chat에서 코드 실행이 꺼져 있을 때 등) 본문을 지어내지 않는다. 설정 › Capabilities에서 코드 실행을 켠 뒤 다시 실행하라고 알리고 멈춘다.

아래 양식을 그대로 출력한다.
`{본문}` 자리에는 파일 내용을 한 글자도 바꾸지 않고 넣는다. 표시선 두 줄도 그대로 쓴다.
이 양식 밖의 설명을 더하지 않는다. 지침 칸에 이미 있는 글과 비교하지도 않는다. 언제 실행하든 같은 글을 준다.

````markdown
**팀 지침을 붙여 넣어 주세요**

1. 아래 글 상자의 복사 버튼으로 전체를 복사합니다.
2. 설정 › General › Instructions for Claude를 엽니다.
3. 칸 맨 위에 붙여 넣고 저장합니다. 내 지침은 끝 표시선 아래에 둡니다.

- Chat과 Cowork가 탭으로 나뉜 화면이면 설정 › Cowork › Global instructions에도 같은 글을 넣습니다.

```text
===== UX팀 지침 시작 · /hello-ux-team이 준 글입니다. 갱신할 때는 끝 줄까지 통째로 바꿉니다 =====
{본문}
===== UX팀 지침 끝 · 내 지침은 이 줄 아래에 씁니다 =====
```

**리드가 갱신을 알렸을 때**

- `/hello-ux-team`을 다시 실행해 새 글을 받습니다.
- 지침 칸에서 시작 표시선부터 끝 표시선까지만 지우고, 그 자리에 새 글을 붙여 넣습니다.
- 표시선 밖의 내 지침은 그대로 둡니다.
````

## 3. 커넥터 점검

모든 화면에서 같다. 도구를 호출하지 않고, 지금 대화에서 쓸 수 있는 도구 목록만 본다.
커넥터 도구 이름은 화면과 연결 방식마다 다르므로 이름을 정해 두고 찾지 않는다.

1. 이름이나 설명에 ClickUp · Slack · Figma가 들어간 도구를 서비스별로 묶는다. 도구 목록이 접혀 이름만 보이면 이름으로 보고, 도구를 찾는 도구가 있으면 서비스 이름으로 검색해 본다.
2. 서비스마다 상태를 정한다.
   - 연결됨: 조회 · 작성 같은 실제 작업 도구가 있다.
   - 로그인 필요: 그 서비스 도구가 로그인 · 인증용뿐이다.
   - 없음: 그 서비스 도구가 하나도 없다.
3. 연결됨이 아닌 것만 아래 표로 알린다. ClickUp과 Slack이 모두 연결돼 있으면 "ClickUp · Slack 모두 연결돼 있습니다." 한 줄로 쓴다. Figma는 연결됨이 아닐 때만 표에 넣는다.

| 커넥터  | 상태               | 연결하는 곳                                                   | 쓰는 스킬                                |
| ------- | ------------------ | ------------------------------------------------------------- | ---------------------------------------- |
| ClickUp | 로그인 필요 · 없음 | Customize › Connectors                                        | `kickoff` · `call-lead` · `decision-log` |
| Slack   | 로그인 필요 · 없음 | Customize › Connectors                                        | `call-lead`                              |
| Figma   | 로그인 필요 · 없음 | Customize › Connectors. `screen-to-hifi`를 쓸 때만 필요합니다 | `screen-to-hifi`                         |

- Code 탭에서는 연결하는 곳을 "Claude 앱의 Customize › Connectors에서 연결한 뒤 Code 탭에서 새 세션을 엽니다"로 쓴다. 커넥터는 세션을 열 때 붙는다.
- 연결과 로그인은 사용자가 직접 한다.

## 4. 안내

결과 끝에 아래를 붙인다.

```markdown
**UX팀 스킬**

| 스킬              | 언제 사용?                                          | 자동 사용 on/off |
| ----------------- | --------------------------------------------------- | ---------------- |
| `hello-ux-team`   | 처음 한 번, 리드가 팀 지침 갱신을 알렸을 때         | off              |
| `kickoff`         | 배정된 프로젝트를 ClickUp 상위 태스크로 등록할 때   | on               |
| `research-report` | 인터뷰 · 설문 · 현장 테스트 메모를 리포트로 만들 때 | on               |
| `screen-to-hifi`  | staging 화면을 Figma로 뜨고 hifi 제안을 얹을 때     | on               |
| `call-lead`       | 프로토타입을 만들다 막혀 리드를 부를 때             | on               |
| `handoff-check`   | 개발로 넘기기 전에 글과 아티팩트를 맞춰 볼 때       | on               |
| `intent-check`    | staging 화면을 기획 의도와 대조할 때                | on               |
| `feature-guide`   | 학원 사용자용 사용 설명서 PDF를 만들 때 (Code 탭)   | on               |
| `tikita-policy`   | 티키타 정책 용어가 나올 때 (준비 중: 위키 연결 전)  | on               |
| `decision-log`    | 정해진 결정을 중앙 컨텍스트에 남길 때               | on               |
| `artifact-style`  | 아티팩트나 HTML 페이지를 만들 때                    | on               |

- 자동 스킬은 상황이 맞으면 스스로 켜지고, 이름으로 불러도 됩니다.
- 하네스 안내 문서: https://claude.ai/artifact/A39pdxytvgJuhiac7Vw3ba
- 다른 화면도 쓰면 그 화면에서도 `/hello-ux-team`을 한 번 실행합니다. Code 탭은 파일에, Chat · Cowork는 설정 칸에 따로 저장됩니다.
```

- 스킬이 어느 교차 지점에서 쓰이는지 사용자가 물으면 `references/_shared/crossings.md`를 읽고 답한다.

## 결과 순서

결론부터 쓰고, 팀원에게 보이는 글은 높임말로 쓴다.

1. 팀 지침: 2-A 결과 문구 또는 2-B 양식. 설치에 실패했으면 "팀 지침 설치 못 함"이 결과의 첫 줄이다
2. 커넥터: 빠진 것만
3. 안내: 스킬 목록, 하네스 안내 문서 링크, 다른 화면 한 줄
