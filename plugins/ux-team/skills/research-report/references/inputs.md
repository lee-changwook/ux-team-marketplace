# 입력 읽기와 QS 데이터

자료를 읽어 리포트의 `PEOPLE` · `GROUPS` · `QS` 세 상수로 옮기는 법.
아래 예시의 학원 · 응답자는 모두 가상이다.

## 데이터 형식

```js
const PEOPLE = [{ key: 'a', name: 'A학원 원장님' }, { key: 'b', name: 'B학원 원장님' }];
const GROUPS = { A: 'A. 지금 미납을 안내하는 방식', B: 'B. 안내 문자에 대한 생각' };
const QS = [
  { n: 1, g: 'A', q: '미납을 확인하면 처음 하는 일부터 순서대로 적어 주세요.',
    opts: { A: '장부 확인', B: '학부모 전화', C: '문자 발송' },
    a: { seq: ['A', 'C', 'B'] }, b: { seq: ['A', 'B'] } },
  { n: 2, g: 'A', q: '미납 안내는 주로 어떻게 하시나요?',
    a: { a: ['문자', '전화'], o: '수업 끝나고 학생 편에 쪽지' }, b: { a: ['전화'] } },
  { n: 7, g: 'B', star: true, q: '안내 문자를 보낼 때 가장 신경 쓰는 점은 무엇인가요?',
    a: { a: '학부모님이 기분 상하지 않게 돌려서 씁니다' }, b: { a: '금액이랑 날짜를 정확하게요' } },
  { n: 9, g: 'B', q: '문자를 보낸 뒤 확인하고 싶었던 적이 있나요?', xq: '있었다면 어떤 상황이었나요?',
    a: { a: ['자주 있었다'], x: '읽었는지 몰라서 다음 날 또 전화했어요' }, b: { a: ['가끔 있었다'] } },
];
```

**PEOPLE**: 응답 세트 둘. 배열 순서가 곧 색이다(첫째 진보라, 둘째 보라). 이름은 리포트에 쓸 호칭 그대로(`A학원 원장님`). 키는 짧은 영문.

**GROUPS**: 문항 묶음 제목. 묶음이 없는 자료면 `{}`로 두고 문항의 `g`를 뺀다.

**문항 필드**

| 필드 | 뜻 |
|---|---|
| `n` | 문항 번호. 본문의 근거 번호 `(4)`와 같은 번호 |
| `g` | 묶음 키 |
| `q` | 문항 원문 |
| `star` | 문항지에서 길게 적어 달라고 표시한 문항(★ · 🔖). 표시가 없는 자료면 긴 서술을 요구하는 문항에만 |
| `opts` | 순서형 문항의 보기표 `{ 키: 보기 원문 }` |
| `xq` | 이어서 답하는 질문의 원문 (`x`를 쓸 때) |

**답 필드** (응답 세트 키 아래)

| 필드 | 뜻 |
|---|---|
| `a` | 문자열이면 서술형, 배열이면 선택형. 기타만 골랐으면 `[]` |
| `o` | 기타 입력 원문 |
| `x` | 이어서 답한 원문 |
| `seq` | 순서형. `opts`의 키를 답한 순서대로 |

답하지 않은 문항은 그 응답 세트 키를 빼면 "답하지 않음"으로 나온다.

**원문 그대로** 옮긴다. 맞춤법, 말줄임표, 띄어쓰기, 줄바꿈(`\n`)까지 그대로 둔다. 응답자 본인이 리포트를 읽을 수 있어, 다듬으면 본인의 말이 아니게 된다. 문자열 안의 작은따옴표만 `\'`로 이스케이프한다.

## 자료별로 읽는 법

### 구글 폼 응답

먼저 CSV를 받는다. 모든 화면에서 된다.
- 사용자에게 응답 탭의 "Sheets에 연결"로 시트를 만든 뒤 CSV로 내려받아 올려 달라고 한다. 읽는 법은 아래 "CSV · 스프레드시트"

응답 화면을 브라우저로 직접 읽는 것은 Code 탭(Chrome 확장) · Cowork(내장 브라우저)에서만 한다. Chat에서는 CSV를 달라고 한다.
- 응답 화면은 로그인이 필요하다. 로그인은 사용자가 직접 한다. 비밀번호를 받거나 입력하지 않는다
- 페이지 글을 읽어 온 뒤 다 읽으면 연 탭을 닫는다
- 응답 탭의 **요약**은 문항별로 모든 사람의 답이 섞여 있고, 서술형 답이 누구의 것인지 표시되지 않는다. 사람별 답은 **개별 보기**에서 응답자를 한 명씩 넘기며 읽는다. 요약은 보기 목록과 응답 수를 확인하는 데만 쓴다
- 선택형 · 순서형의 보기 목록과 순서는 질문 탭에서 확인한다
- 페이지를 끝까지 읽기 어려우면 CSV로 바꾼다

어느 길이든
- 응답자 목록에 대상이 아닌 사람(작성자 본인의 시험 응답 등)이 있으면 빼고, 표지 `대상` 칸에 괄호로 적는다 (`A학원 원장님, B학원 원장님 (시험 응답은 제외)`)
- 응답자를 제출 이메일로만 알 수 있고 그 이메일이 낯설면, 추정하지 말고 사용자에게 묻는다

### CSV · 스프레드시트

- Python `csv` 모듈로 읽는다. 첫 행이 문항, 이후 행이 응답자
- 타임스탬프 · 이메일 · 이름 · 소속 같은 식별 열은 QS에 넣지 않는다. 누구의 응답인지 가리고 표지 `대상` 칸을 채우는 데만 쓴다. 응답 날짜는 타임스탬프에서 가져온다
- QS 문자열은 손으로 옮겨 적지 말고 CSV에서 스크립트로 만든다. 원문이 한 글자도 바뀌지 않는다
- 체크박스 다중 선택은 한 칸에 `, `로 합쳐져 있다. 보기 원문에도 쉼표가 들어 있을 수 있으니(`지금 쓰는 프로그램(문자, 알림톡 등)`) 쉼표로 자르지 말고 보기 목록과 맞춰 나눈다. 구글 폼은 **기타 입력을 맨 뒤에** 붙이므로, 보기 목록에 없는 조각이 맨 뒤에 있으면 `o`(기타)다
- 순서형은 폼 형식에 따라 `C → B → E` 같은 단답이거나 ` > `로 이어진 보기 원문이다. 칸 몇 개를 먼저 보고 구분자를 정한 뒤 `opts`의 키로 바꾼다
- 응답자 행이 셋 이상이면 SKILL.md 0절 "응답 세트가 셋 이상이면"을 따른다

### 문항지와 폼이 다를 때

문항지는 폼을 만들기 전 판일 수 있다. **응답이 실제로 받은 문항과 보기(폼 · CSV)가 정답**이다. 문항지에서는 묶음, ★ 표시, 보기 순서처럼 폼에 없는 정보만 가져온다.

### 회의록 · 녹음 요약

- 사용자가 준 텍스트나 내보낸 파일을 읽는다
- 인터뷰 자체의 녹음 요약이면 질문과 답으로 쪼개 QS로 옮긴다 (아래 "인터뷰 메모"와 같다)
- 팀 회의록은 문항 답이 아니라 **제안의 근거**다. 회의에서 나온 제안 · 결정은 비교 카드의 설명과 제안 섹션에 반영하고, 출처를 밝힌다
- 쓴 회의록은 표지 `자료` 칸에 날짜와 함께 적는다 (`10월 2일 기획 회의 요약`)

### markdown 문서

- **문항지**: 묶음 · ★ 표시 · 보기 순서의 원천. 문항 문구와 보기는 폼을 따른다 (위 "문항지와 폼이 다를 때")
- **인터뷰 메모**: 질문과 답으로 쪼개 QS로 옮긴다. 답은 메모에 적힌 문장 그대로, 모두 서술형(`a`: 문자열)
- **질문 리스트**: 작성자가 현장에서 질문 아래 들여쓴 목록으로 답을 적은 문서. 손으로 옮기지 말고 `scripts/md_to_qs.py`로 옮긴다. 형식과 규칙은 스크립트 머리말에 있다
  - 파일 하나: 단일형 QS(답 키 `r`)와 문항 수를 낸다
  - 파일 둘(응답 세트 둘이 같은 질문 리스트에 답함): `--keys a,b`로 같은 문항끼리 짝짓고, 양쪽 모두 답한 비율과 판정(비교형 / 단일형 / 애매함)을 낸다
  - 답 줄 끝의 `(녹음)`은 떼고 옮긴다. 녹음 요약에서 보탠 줄이라는 표시일 뿐이다. `(제안)`으로 끝나는 줄은 작성자의 아이디어라 응답에서 빼고, 필요하면 제안 섹션에 쓴다
  - 질문 리스트 앞쪽의 메모(계정 · 비밀번호 · 연락처 등 `## 키.` 섹션 밖의 줄)는 읽지 않는다
  - 파일이 셋 이상이면 SKILL.md 0절 "응답 세트가 셋 이상이면"을 따른다

### 단일형 QS

비교형과 같은 필드를 쓰되 답 키가 하나(`r`)다. `PEOPLE`은 쓰지 않는다.

```js
const GROUPS = { A0: '지금 쓰는 방식 관찰: 출석 확인' };
const QS = [
  { n: 7, g: 'A0', q: '학생이 들어오면 출석을 어디에 적나요? [사진 촬영]', r: { a: '데스크 종이 출석부에 체크\n…' } },
];
```
