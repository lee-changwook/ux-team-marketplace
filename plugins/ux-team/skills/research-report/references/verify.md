# 검증과 PDF

## 스크린샷 — `scripts/shot.py` (Code 탭 전용, 선택)

Code 탭이고 Chrome이 설치돼 있을 때만 쓴다. 헤드리스 Chrome으로 찍어서 사용자 화면이나 브라우저를 건드리지 않는다. 결과 PNG는 임시 폴더에 두고 열어 본다.
다른 화면이거나 Chrome이 없으면 건너뛰었다고 알리고, 아래 "볼 것"을 사용자가 HTML을 열어 눈으로 확인하게 한다.

```bash
SHOT="python3 $SKILL/scripts/shot.py"   # $SKILL은 SKILL.md가 있는 폴더
$SHOT "<리포트>.html" <임시 폴더>/top.png                                  # 표지부터
$SHOT "<리포트>.html" <임시 폴더>/cmp.png --hide ".hero, #summary, #answers" # 비교부터
$SHOT "<리포트>.html" <임시 폴더>/m.png --width 390 --height 3000            # 휴대폰 폭
$SHOT "<리포트>.html" <임시 폴더>/print.png --width 703 --print              # 인쇄 레이아웃
```

- 스크롤이 안 된다. 뒤쪽 섹션은 `--hide`로 앞 섹션을 숨기고 찍는다. 섹션 id는 `summary` · `answers` · `compare` · `support` · `proposal`, 표지는 `.hero`
- 한 장에 2초쯤 걸린다. 스크립트가 한글 경로 복사, Chrome이 종료하지 않는 문제, 500px보다 좁은 폭을 처리한다

### 볼 것

- 표지: 한 문장 결론이 2~3줄 안, 메타 정렬
- 모든 섹션이 왼쪽 레일 + 본문 그리드 하나에 맞춰 정렬되는지
- 문항 목록: 묶음 제목, 번호 칸, 책갈피 아이콘(★ 문항), 순서형 칩이 줄바꿈될 때 칩과 화살표가 함께 넘어가는지
- 비교: 연보라 띠 위 흰 카드, 진한 배지 카드만 진보라 테두리. 결정 칩이 두 줄로 꺾이면 문구를 줄인다
- 비교형: 가운데 세로선, 두 응답 세트 이름 줄이 묶음마다 반복되는지
- 60:30:10이 깨지지 않았는지. 진보라가 비교 섹션 밖에서 과하게 쓰이면 POL-01 위반이다

## 문장 점검 (POL)

- [ ] 문항 목록에 배지 · 강조가 없다 (POL-01)
- [ ] 대문자 라벨, 가운뎃점 메타 문자열, 링크 뒤 `→`가 없다. 결정 칩은 쌍점 (POL-02)
- [ ] 번호가 흐름 · 우선순위 · 문항에만 있다 (POL-03)
- [ ] 영어 직역투가 없다. 소리 내어 읽어 어색한 문장을 고친다 (POL-04)
- [ ] `check_shared.py` 금지 0건, 경고는 하나씩 읽고 합니다체로 고친다 (POL-05)
- [ ] 대결 카드 6~8장, 진한 배지 3장 안팎 (비교형). 단, 같은 질문에 답이 갈린 곳이 모자라면 채우지 않는다
- [ ] 카드마다 양쪽이 **같은 질문**에 답한 것인지 문항 번호로 확인한다. 사실 vs 의견, 답 없음, 자료 밖 정보가 짝지어져 있지 않다 (POL-06)
- [ ] 역할 3열(`.roles`)이 지워졌고, 준비 섹션 이름이 "먼저 살펴볼 것"이다 (SKILL.md 4절)
- [ ] 응답 원문이 바뀌지 않았다. 자료의 답과 QS를 스크립트로 대조한다. 단일형은 `md_to_qs.py`를 다시 돌려 리포트 QS와 diff한다

## PDF — 요청할 때만 (`scripts/to_pdf.py`)

PDF는 자동으로 만들지 않는다. 사용자가 PDF를 달라고 할 때만 만든다. 템플릿에는 A4 인쇄 CSS가 들어 있다.

```bash
python3 "$SKILL/scripts/to_pdf.py" "<리포트>.html"            # 리포트 옆에 같은 이름의 .pdf
python3 "$SKILL/scripts/to_pdf.py" "<리포트>.html" --check    # 만들 수 있는지만 본다
```

스크립트가 하는 일
- 브라우저를 찾는다: macOS의 Chrome · Chromium · Edge 앱, `PATH`의 `chromium` · `google-chrome` 등, Playwright가 받아 둔 Chromium
- 리눅스 실행 환경이면 한글 글꼴이 있는지 본다. 없으면 글자가 네모로 깨지므로 만들지 않는다
- 한글 경로는 임시 폴더에 ASCII 이름으로 복사해서 돌린다. 헤드리스 Chrome은 PDF를 쓰고도 종료하지 않을 때가 있어 시간 제한을 건다
- 브라우저나 글꼴이 없으면 종료 코드 3과 이유를 낸다. 대안은 SKILL.md 6절

**인쇄 레이아웃 확인**: PDF 페이지를 이미지로 볼 도구가 없으면, Code 탭에서 `shot.py --print --width 703`으로 대신 확인한다. macOS에서는 `qlmanage -t -s 1400 -o <임시 폴더> <리포트>.pdf`로 첫 쪽을 PNG로 볼 수 있다.

- 표지 다음 섹션이 새 페이지에서 시작하는지 (`break-before: page`)
- 카드 · 행이 페이지 경계에서 잘리지 않는지 (`break-inside: avoid`)
- A4 폭에서는 900px 반응형 규칙이 먹는다. 공통점 2열 · 흐름 3열은 인쇄 블록에서 다시 지정돼 있다
