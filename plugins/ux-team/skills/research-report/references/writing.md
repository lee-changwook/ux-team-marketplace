# 문장과 섹션 쓰는 법

아래 예시의 학원 · 응답자는 모두 가상이다.

## 공통 규칙

**POL-01 대비와 강조는 비교 섹션 한 곳에만.** 문항 목록에는 배지나 강조를 넣지 않는다. 문항 목록은 원문을 보여 주는 곳이고, 강조가 섞이면 응답이 평가받는 것처럼 보인다.

**POL-02 쓰지 않는 표기**
- 대문자 라벨 (`SUMMARY`, `text-transform: uppercase`)
- 가운뎃점으로 이은 메타 문자열 (`2026-10-02 · 응답 2건 · 20문항`). 결정 칩도 `우선순위: 원장님, 실장님`처럼 쌍점으로 쓴다. 보기 원문에 들어 있는 가운뎃점(`문자 · 알림톡`)은 원문이라 그대로 둔다
- 링크 뒤 `→`
- 문항 근거는 문장 안에서 `(4)`처럼 괄호로. 요약 항목 끝에서는 `.ref` 칸에 숫자만 (`4, 20`)

**POL-03 번호는 실제 순서가 있는 것에만.** 흐름, 우선순위, 설문 문항. 나열에 번호를 붙이면 순서가 있는 것처럼 읽힌다.

**POL-04 네이티브 한국어.** 영어 직역투와 맥락에 맞지 않는 말을 피한다. 고친 예:

| 전 | 후 |
|---|---|
| 제품 코드는 언제 열까요? | 코드는 언제 구현해 볼까요? |
| 개선 방향을 정하기 위한 출발점 | 개선 방향을 정할 때 참고하려고 만들었습니다 |
| 사람에서 시작합니다 | 사용자부터 봅니다 |
| 넘기는 형태 | 전달 방식 |
| 두 분이 같은 곳 | 두 분의 공통점 |

**POL-06 다른 질문의 답을 짝짓지 않는다.** 대결 카드와 나란히 놓는 비교는 **같은 질문을 두고 답이 갈린 곳만** 만든다. 카드 수 기준(비교형 6~8장)보다 이것이 먼저다. 모자라면 적게 만들고, 없으면 비교 섹션을 지운다. 짝짓지 않는 것:
- 서로 다른 질문의 답 (팝업 모양 vs 알림 위치 평가)
- 사실과 의견 (지금 쓰는 방식이 어떻게 돌아가는지 vs 새 화면에 대한 반응)
- 한쪽이 답하지 않은 문항 ("못 물어 봄"과 대결시키지 않는다)
- 대상에 관한 답이 아닌 것 (현장 환경 답을 한 대상 칸에, 다른 프로그램 이야기를 다른 대상 칸에)
- 자료 밖의 정보 (코드에서 확인한 상태를 인터뷰 결과처럼)

같은 것을 묻는 질문에 같은 방향으로 답했으면 대결이 아니라 공통점(`same`)에 둔다. 억지로 짝지은 카드는 결과를 왜곡했다는 지적을 받는다.

**원문은 그대로.** 문항과 답은 QS 데이터로만 들어가고, 본문에서 답을 줄여 쓸 때도 뜻을 바꾸지 않는다. 요약 칸(facts)과 비교 카드의 양쪽 답은 원문을 줄인 말이라 명사형으로 다듬어도 된다(`가끔 쓴다` → `가끔 사용`).

**이름.** 응답자는 `홍길동 원장님`처럼, 실명 대신 소속과 직함으로 부를 때는 `A학원 원장님`처럼. 이름과 호칭 사이는 `&nbsp;`로 묶어 줄바꿈에 갈리지 않게 한다.

**표지 kicker.** 굵은 줄은 리서치 이름(`미납 안내 인터뷰 정리`), 아랫줄은 응답 날짜(`2026년 10월 2일 응답`). 응답 날짜가 여러 날이면 기간으로.

## 섹션 이름과 배지

이 스킬은 학원 사용자 리서치(인터뷰 · 설문 · 현장 테스트)를 정리한다. 목적은 제품 개선 방향을 찾는 것이다.

| 자리 | 쓰는 말 |
|---|---|
| 진한 배지 | 함께 정할 것. 인터뷰에서 함께 정하고 싶은 부분 |
| 보완 배지 | 보완. 같은 문제를 다른 쪽에서 보여 주는 차이 |
| 준비 섹션 | 먼저 살펴볼 것 (만들기로 정한 목록이 아니라 먼저 여쭤볼 순서임을 밝힌다) |
| 제안 섹션 | 개선 방향 제안 / "이런 흐름은 어떨까요?" |
| 제안 구성 요소 | 흐름(개선안) → 현황 표(지금 방식, 자료에 사실이 있을 때만) → 함께 이야기할 것. 역할 3열은 쓰지 않는다 |

제품이 무엇을 해 주겠다고 약속하는 것처럼 읽히지 않게 쓴다.

## 비교형

응답 세트 둘이 같은 질문에 답한 자료를 나란히 정리한다. 독자는 응답자 본인일 수 있고, 슬랙 등으로 올라가면 누구나 볼 수 있다. 평가받거나 통보받는 느낌이 들지 않게 쓴다. 문체는 합니다체.

### 쓰지 않는 것 (POL-05)

- 응답자 추정 문구 (누구의 응답인지 추정한 근거 등)
- "가설로 본다" 같은 불신 표현
- 사람을 점수나 축 위에 놓는 표현
- 응답자를 평가하거나 결과물로 검증하겠다는 항목
- 작성자 혼자 확인할 것 (자료 대조 등)
- 응답자별 성과 지표 ("보는 숫자", KPI)
- 내부 자료 이름. 표지 `자료` 칸에는 응답자가 알아볼 수 있는 자료만 적는다

### 바꿔 쓰는 표현

| 쓰지 않음 | 쓴다 |
|---|---|
| 평서체 `~다` | 합니다체. 공통점 카드 같은 짧은 항목도 (`두 분 모두 자주 있었습니다`) |
| 조정 필요 | 함께 정할 것 |
| 조정 방향 서술 | "…하면 어떨까요?" |
| 약점식 (`문자를 보내고 확인을 못 한다`) | 강점식 (`직접 통화로 바로 확인하는 데 익숙합니다`) |
| 레일 | 먼저 살펴볼 것 |
| 게이트 | 결정 |
| 1 · 2 · 3단계 | 기획 문서 / 동작하는 화면 / 실제 서비스처럼 이름으로 |
| 읽는 법 | 이 문서는 (무엇을 정리했고 무엇에 참고하려는지) |

### 제목

응답자를 평가하는 듯한 제목을 피한다. `원장님 성향 분석` 대신 `미납 안내 인터뷰 정리`처럼 주제로 짓는다. 사용자가 제목을 주면 그대로 쓴다.

### 섹션별

**표지**
- `h1`: 두 응답 세트의 출발점을 대구로 한 문장 (`A학원은 문자부터, B학원은 전화부터 안내합니다.`). 짧을수록 좋다
- `lede`: 둘이 어떻게 다르고 그 차이가 어떻게 서로를 채우는지 두 문장
- `meta`: 대상, 자료, 이 문서는(무엇에 참고하려고 만들었는지 + 숫자는 근거 문항 번호)

**요약** (둘 나란히)
- `persona`: 강점식 한 줄 (`장부부터 보고, 문자로 먼저 알립니다`)
- `findings` 3개: 끝에 근거 문항 번호
- `facts` 6칸: 비교하기 좋은 축을 골라 명사형 값으로. **라벨은 둘이 같아야** 나란히 읽힌다

**문항별 답변**: 렌더러가 그린다. 레일 설명만 쓴다.

**비교**
- 대결 카드는 **결론에 쓰이는 차이만 6~8장** 고른다. 답이 갈린 문항을 전부 카드로 만들면 강조가 무뎌진다. 같은 질문에 답이 갈린 곳이 6장보다 적으면 채우지 않는다 (POL-06)
  - 같은 주제의 문항은 한 장으로 묶는다 (안내 순서 1 + 안내 수단 2)
  - 한 문항 안에서 일부만 다르면 다른 부분만 카드로, 같은 부분은 공통점으로
  - 보완도 함께 정할 것도 아닌 사소한 차이(쓰는 기기 이름 등)는 카드로 만들지 않는다. 문항 목록과 요약에 이미 있다
- `함께 정할 것`(진한 배지)은 3장 안팎. 나머지는 `보완`
- `why`: 차이가 뜻하는 것, 또는 "…하면 어떨까요?" 한 줄
- 공통점 4개 안팎. 완전히 같은 답이 없으면 같은 방향의 답

**먼저 살펴볼 것**: 우선순위 순 5개 안팎. 무엇을 하는지와 왜인지를 근거 번호와 함께. 만들기로 정한 목록이 아니라 먼저 살펴볼 순서임을 레일에 밝힌다.

**제안**
- 레일 설명에 **확정된 내용이 아님**을 적는다
- `ask` 한 줄로 연 뒤 `verdict-line` 한 문장 제안
- 구성 요소는 위 "섹션 이름과 배지" 표의 것만. 역할 3열(`.roles`)은 지운다

**함께 이야기할 것** 4개 안팎
- 함께 정할 것 카드마다 질문 하나
- 응답자에게 직접 물을 수 있는 것만. 작성자 혼자 확인할 것은 넣지 않는다
- 답이 서로 엇갈려 읽기 애매한 곳은 판단하지 말고 여기서 묻는다
- 마지막 항목은 제안 전체가 응답자 생각과 맞는지 묻는다

다 쓰면 `scripts/check_shared.py`로 남은 표현을 찾는다.

## 단일형

한 곳을 인터뷰했거나, 섹션마다 질문이 다른 질문 리스트(예: 지금 쓰는 방식 관찰 + 새 화면 테스트 반응)를 정리한다. 독자는 팀이나 전사다. 문체와 "쓰지 않는 것 · 바꿔 쓰는 표현"은 비교형과 같다. 예시는 `examples/단일형/`.

**표지**
- `h1`: 가장 중요한 발견 한 문장. 두 대상을 대결시키는 대구로 쓰지 않는다 (`출석은 10초 안에 끝났고, 현장은 늦은 학생을 먼저 보고 싶어 합니다.`)
- `lede`: 결론을 푸는 두 문장
- `meta`: 대상(실명 대신 소속과 직함도 됨), 자료, 현장 환경(환경 문항이 있을 때만, 두세 문장), 이 문서는(어떤 순서로 정리했는지 + "나란히 놓은 것은 같은 질문을 두고 답이 갈린 곳뿐" + 숫자는 근거 문항 번호)

**요약**
- 대상이 둘이면 나란히, 하나면 한 열. 레일에 "같은 줄에 있어도 서로 짝지은 내용은 아닙니다"를 적는다
- `persona` 한 줄, `findings` 3개, `facts` 6칸. facts 라벨은 대상끼리 맞추지 않는다. 그 대상에 답이 있는 것만

**문항별 답변**: `md_to_qs.py` 출력을 그대로. 자료의 순서와 묶음을 바꾸지 않는다. 레일에 녹음 요약 등에서 보탠 내용이 있으면 그렇다고 적는다.

**비교**
- 같은 질문에 답이 갈린 곳만 (POL-06). 축 옆에 양쪽 문항 번호를 모두 적는다 (`늦은 학생 표시 (6, 14)`)
- 공통점 제목은 `<대상1>과 같은 방향인 것`처럼, 무엇과 같은 방향인지 드러낸다
- 레일에 갈린 곳이 몇 곳인지 적는다

**먼저 살펴볼 것**: 사용자가 실제로 부딪히는 순서(예: 학생이 들어와서 수업이 시작될 때까지)로. 묻지 못한 문항에서 나온 항목은 "여쭤보지 못했습니다"라고 그대로 적는다.

**제안 · 함께 이야기할 것**: 비교형과 같다. 현황 표는 자료에 있는 사실로만 채울 수 있을 때만 둔다. 제안에 작성자의 아이디어가 들어가면(예: 묻지 못한 문항에 대한 해법) 레일에 그렇다고 밝힌다.
