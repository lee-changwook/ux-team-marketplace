# kickoff

전사 미팅에서 배정된 프로젝트를 팀 스페이스에 상위 태스크로 등록합니다.
교차 지점 "입구"의 형식을 대신 지켜 줍니다 (`references/_shared/crossings.md`).
상위 태스크가 만들어진 시각이 리드타임의 시작입니다.

## 어디서 되는가

- Chat · Cowork · Code 탭 모두 같습니다. ClickUp 커넥터만 씁니다.
- ClickUp 커넥터가 연결되어 있지 않으면 Customize › Connectors에서 ClickUp을 연결하라고 안내하고 멈춥니다.

## 하지 않는 것

- 확인 없이 만들지 않습니다 (ACC-34).
- 기존 태스크를 고치지 않습니다. 기존 태스크 수정은 이 스킬이 맡지 않습니다.
- 위치 · 담당 · 배경을 지어내지 않습니다. 모르면 묻거나 `미결`로 둡니다.
- 태스크 상태를 고르지 않습니다. 리스트의 첫 상태를 그대로 둡니다.

## 진행 순서

### 1. 장소 읽기

- `references/_shared/team-places.md`의 ClickUp 표에서 "상위 태스크" 행을 읽습니다.
- Space나 List가 `<미정>`이면 사용자에게 묻습니다: "상위 태스크를 둘 Space와 List 이름(또는 리스트 링크)을 알려 주세요."
- 받은 위치가 커넥터에서 보이지 않으면 그 사실을 알리고 다시 묻습니다. 비슷한 이름의 리스트를 골라 쓰지 않습니다.

### 2. 입력 모으기

| 값 | 필수 | 없을 때 |
|---|---|---|
| 프로젝트 이름 | 필수 | 묻습니다 |
| 프로젝트 번호 `PRJ-NNN` | 선택 | 전사 미팅에서 번호를 받았는지 한 번 묻고, 없으면 이름만 씁니다 |
| 배정일 | 필수 | 묻습니다. "오늘" · "어제"는 날짜로 바꿉니다 |
| 담당 | 필수 | 묻습니다. 커넥터에서 그 사람을 찾아 초안에 보여 줍니다 |
| 배경 | 필수 | 모르면 `미결`로 둡니다 |
| 마감일 | 선택 | 비웁니다 |

- 대화에 이미 나온 값은 다시 묻지 않습니다.

### 3. 같은 이름 먼저 찾기 (ACC-35)

초안을 만들기 전에 1단계의 리스트에서 찾습니다.

- 범위는 리스트 전체입니다. 닫힌 태스크 · 보관된 태스크도 포함합니다.
- 비교할 때는 이름 앞의 `[PRJ-NNN]`, 공백, 대소문자를 떼고 봅니다.
  - 남은 이름이 같으면 "같은 이름"입니다.
  - 한쪽이 다른 쪽을 품으면 "비슷한 이름"입니다.
  - `PRJ-NNN` 번호가 같으면 이름이 달라도 함께 알립니다.
- 찾으면 초안보다 먼저 이름 · 상태 · 담당 · 링크를 보여 주고 고르게 합니다.
  - 새로 만들기 / 기존 태스크 쓰기 / 그만두기
  - 고르는 것은 사용자입니다. 기존 태스크를 쓰기로 하면 링크만 주고 끝냅니다.
- 찾기가 실패하면(커넥터 오류, 리스트를 끝까지 못 읽음 등) 만들지 않고 알립니다. 찾지 못한 채로 만들면 같은 이름을 알릴 수 없기 때문입니다.

### 4. 초안 보여 주기

아래 양식을 그대로 채워 보여 줍니다.

```
위치: Space › List
이름: [PRJ-NNN] 프로젝트 이름        (번호가 없으면 이름만)
담당: 담당 기획자
시작일: 배정일 YYYY-MM-DD
마감일: YYYY-MM-DD 또는 비움
설명:
  ## 배경
  - …  (모르면 미결)
  ## 배정
  - 전사 미팅 YYYY-MM-DD
  ## 미결
  - …  (없으면 이 절을 지웁니다)
서브태스크: 개발 전달
```

- 서브태스크 "개발 전달"은 CRS-04 핸즈오프에서 완료로 바꾸는 기록입니다 (`crossings.md`).
- 초안 아래에 "이대로 만들까요? 고칠 곳이 있으면 알려 주세요."라고 묻습니다.
- 글은 `references/_shared/writing.md`를 따릅니다. "확정"이라고 쓰지 않습니다.

### 5. 확인받기

- "만들어 주세요" · "좋아요, 진행해 주세요"처럼 분명히 답했을 때만 만듭니다.
- 고칠 점을 받으면 초안을 고쳐 다시 보여 주고 다시 묻습니다.
- 답이 애매하면 만들지 않고 다시 묻습니다.

### 6. 만들기

1. 상위 태스크를 만듭니다.
2. 그 아래에 서브태스크 "개발 전달"을 만듭니다.

- 상위 태스크 만들기가 실패하면 서브태스크로 넘어가지 않고 실패를 알립니다.
- 서브태스크만 실패하면 상위 태스크 링크와 실패 사실을 함께 알리고, 다시 만들지 묻습니다.

### 7. 링크 주기 (ACC-36)

- 만든 상위 태스크와 서브태스크의 링크를 줍니다.
- 다음 한 줄을 덧붙입니다.
  - "막히면 `call-lead`로 리드를 부르고, 결정이 나면 `decision-log`로 남길 수 있습니다."
