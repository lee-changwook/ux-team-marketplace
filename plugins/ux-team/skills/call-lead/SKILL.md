# call-lead

CRS-03 중간 확인에서 리드를 부릅니다 (`references/_shared/crossings.md`).
내용은 프로젝트 상위 태스크의 ClickUp 댓글에 남기고, Slack에는 그 댓글 링크와 리드 멘션만 보냅니다 (DEC-06).
기록은 ClickUp에 남고, Slack은 알리는 데만 씁니다.

## 어디서 되는가

- Chat · Cowork · Code 탭 모두 같습니다. ClickUp · Slack 커넥터만 씁니다.
- 두 커넥터 중 연결되지 않은 것이 있으면 Customize › Connectors에서 연결하라고 안내하고 멈춥니다. 한쪽만 하고 끝내지 않습니다.

## 하지 않는 것

- 댓글도 Slack도 확인 없이 보내지 않습니다 (ACC-40).
- Slack 본문에 댓글 내용을 옮겨 적지 않습니다 (ACC-41).
- 리드 한 명만 멘션합니다 (ACC-42). ClickUp 댓글 안에서는 멘션하지 않습니다.
- 상위 태스크가 없을 때 Slack에 바로 보내지 않습니다.
- 채널 · 스레드를 지어내지 않습니다. 모르면 묻습니다.

## 진행 순서

### 1. 장소 읽기

- `references/_shared/team-places.md`를 읽습니다.
  - ClickUp 표의 "상위 태스크" 행: 상위 태스크를 찾을 리스트
  - Slack 표: 용도 · 어떤 질문을 보내나 · 채널
  - 멘션할 리드의 표시 이름
- 값이 `<미정>`이면 그 값이 필요한 단계에서 묻습니다.

### 2. 입력 모으기

| 칸 | 내용 | 없을 때 |
|---|---|---|
| 여쭤볼 것 | 리드가 답해야 하는 질문 | 묻습니다. 질문 없이 부르지 않습니다 |
| 막힌 지점 | 어디서 무엇이 안 되는지 | 묻습니다 |
| 불확실한 데이터 구조 | 모르는 필드 · 관계 · 값 | 모르면 `미결`, 해당 없으면 "없음" |
| world 브랜치 | 구현 중인 브랜치 이름 | 묻고, 없으면 "없음" |
| 재현 방법 | 리드가 같은 상태를 보는 순서 | 묻고, 모르면 `미결` |

- 티키타 정책 질문(용어 · 청구 · 출결 같은 규칙)이면 먼저 `tikita-policy`로 찾아보라고 안내합니다. 위키에 답이 없을 때 부릅니다.

### 3. 상위 태스크 찾기

- 링크를 받으면 그 태스크를 씁니다.
- 이름만 받으면 1단계의 리스트에서 찾습니다. 후보를 이름 · 상태 · 링크로 보여 주고 고르게 합니다.
- 리스트가 `<미정>`이면 상위 태스크 링크를 달라고 합니다.
- 상위 태스크가 없으면 `kickoff`로 먼저 등록하라고 안내하고 멈춥니다.

### 4. 댓글 초안 → 확인 → 게시

아래 양식을 그대로 채워 보여 줍니다.

```
[중간 확인] 한 줄 요약

## 여쭤볼 것
- …

## 막힌 지점
- …

## 불확실한 데이터 구조
- …  (미결 · 없음)

## world 브랜치
- 브랜치 이름

## 재현 방법
1. …
```

- 질문을 맨 위에 둡니다. 글은 `references/_shared/writing.md`를 따릅니다.
- 초안 위에 올릴 태스크(이름 · 링크)를 적고 "이 댓글을 올릴까요?"라고 묻습니다.
- 분명히 승인했을 때만 올립니다. 고칠 점을 받으면 고쳐서 다시 묻습니다.
- 올린 뒤 댓글 링크를 받아 둡니다. 올리기가 실패하면 Slack 단계로 가지 않고 알립니다.

### 5. 채널 고르기

- Slack 표의 "어떤 질문을 보내나" 칸과 2단계의 질문을 맞춰 봅니다.
  - 맞는 행이 하나면 그 행을 후보로 둡니다.
  - 여럿이 맞거나 맞는 행이 없으면 행들을 보여 주고 고르게 합니다.
  - 채널이나 고르는 기준이 `<미정>`이면 어느 채널에 보낼지 묻습니다.
- 고른 채널은 6단계 초안에 함께 보여 주어 사용자가 확인합니다.

### 6. 스레드 찾기

- 고른 채널에서 이 상위 태스크의 스레드를 찾습니다. 상위 태스크 이름과 태스크 링크로 찾습니다.
  - 하나가 나오면 그 스레드에 답글로 답니다.
  - 여럿이 나오면 후보를 보여 주고 고르게 합니다.
  - 없으면 새 스레드를 엽니다.
- 찾기가 실패하면 그 사실을 알리고, 스레드 링크를 받을지 새 스레드를 열지 묻습니다.

### 7. Slack 초안 → 확인 → 발송

- 표시 이름으로 리드를 Slack 커넥터에서 찾습니다. 찾은 사람(이름 · 표시 이름)을 초안에 함께 보여 줍니다. 못 찾거나 여럿이면 묻습니다.
- 양식은 둘 중 하나입니다.

```
새 스레드:    [PRJ-NNN] 프로젝트 이름 · 중간 확인 <댓글 링크> @리드
스레드 답글:  <댓글 링크> @리드
```

- 새 스레드 첫 줄의 태스크 이름은 스레드를 다시 찾기 위한 표지입니다. 그 밖의 내용은 넣지 않습니다.
- 초안 위에 채널 · 스레드(새 스레드인지, 어느 스레드의 답글인지)를 적고 "이대로 보낼까요?"라고 묻습니다.
- 다른 사람도 부르고 싶다고 하면, Slack에서는 리드만 부르고 다른 사람은 ClickUp 댓글에서 부르라고 안내합니다.
- 분명히 승인했을 때만 보냅니다. 스레드 답글을 채널에도 함께 보내는 옵션은 끕니다.

### 8. 링크 주기

- 댓글 링크와 Slack 메시지 링크를 줍니다.
- 다음 한 줄을 덧붙입니다.
  - "Slack에서 논의가 길어지면 결론을 이 댓글에 옮겨 주세요. 결정이 나면 `decision-log`로 남길 수 있습니다."
