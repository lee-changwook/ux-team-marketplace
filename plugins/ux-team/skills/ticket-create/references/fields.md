# 컬럼 의미와 적용 규칙

이 문서는 표준안입니다. 실제로 존재하는 컬럼 목록이나 ID의 정본이 아닙니다.
등록할 목록의 실제 칸·선택지를 읽고, 아래 의미에 맞는 칸이면 이름이 달라도 매핑합니다.
값은 입력에서 판단해 채울 수 있는 칸을 모두 채우고, 초안의 컬럼 표로 보여 확인받습니다. 사용자가 그 표를 확인하면 매핑도 승인된 것으로 봅니다.
초안만 작성할 때는 아래 의미로 값 후보를 보여 주되 실제 적용 여부는 미확인으로 둡니다.

## 접수 정보

| 의미 | 표준 형식·값 | 값이 없을 때 |
|---|---|---|
| 유형 | 기존 오류사항/개선사항 목록으로 구분 | 초안은 미확인. 등록 전 대상 목록 확인 |
| 제품 | 티키타 웹 / 티키타 앱 / 티링 / 모바일 결제 / 강사 성적표, 복수 선택 권장 | 화면·기능·앱 이름과 선택지로 판단해 고름. 두 제품에 걸치면 묶음 선택지가 있을 때만 쓰고, 애매하면 비우고 확인 질문에 넣음 |
| 환경 | 운영 / 스테이징 / 개발 / 미확인 | 본문에 미확인. 실제 ‘미확인’ 옵션이 있을 때만 선택 |
| 업무 영역 | 계정·권한 / 재원생·보호자 / 등록·입반 / 수업 / 출결 / 청구·수납·결제 / 알림·문자 / 소식·학습 / 공통 / 미분류 | 분명하지 않으면 미분류 또는 본문에 미확인 |
| 요청 기관 | 요청이 나온 기관. 복수 기관 지원 권장 | 입력에 나온 기관을 선택지에서 고름. 띄어쓰기·약칭만 다르면 같은 선택지. 없으면 필수 컬럼일 때 등록 전에 확인. ‘전체 기관 영향’으로 해석하지 않음 |
| 접수 경로 | 카카오톡 / 티링문의 / 구두접수 / Slack / 인터뷰 / 내부 테스트 / 기타 | 입력에 나온 접수 방식과 같은 뜻의 선택지(예: 카톡 → 카카오톡). 근거 없으면 비움 |
| 요청자 | 외부 요청자의 이름·역할 또는 내부 발견자 | 작성자·담당자와 같다고 추정하지 않음 |
| 접수 담당자 | 후속 확인·회신 담당자. 선택지가 사람 이름인 커스텀 ‘담당자’ 칸 | 입력에 나온 회신 담당자. 없으면 작성자가 선택지에 있을 때 작성자. 기본 담당자(작업 배정)와 다른 칸 |
| 발견 버전 | 제품 버전, 텍스트 | 비움. `직접 입력`이나 `최신`을 실제 버전으로 간주하지 않음 |
| 확인 빌드·커밋 | 기술 확인 담당자가 확인한 빌드 또는 커밋, 텍스트 | 비움 |
| 생성일·접수일 | 티켓을 접수한 날짜 | 입력에 날짜가 있으면 그 날짜, 없으면 작성일(오늘). 모호한 상대 날짜는 확인 |
| 발생 시점 | 사용자가 제공한 시점, 필요한 경우만 | 생성 시각으로 대체하지 않음 |

## 처리·후속 관리 정보

| 의미 | 표준 형식·값 | 이 스킬의 기본 처리 |
|---|---|---|
| 실제 처리 담당자 | 기본 담당자 기능 | 명시적으로 지정한 작업 담당자만 배정. 요청자·접수자를 자동 배정하지 않음 |
| 우선순위·기한 | 기본 우선순위·마감일 | 명시된 값만(예: 중요도 높음·중·낮음 → High·Normal·Low). 업무 영향을 보고 임의 설정하지 않음 |
| 정보 상태 | 미검토 / 보완 필요 / 충족 | 초기값은 미검토. 사용자가 확인한 검토 결과가 있을 때만 반영 |
| 처리 분류 | 미분류 / FE / BE / 기획 / 프로젝트 / 검토 / 대응 불필요 | 초기값은 미분류. 조사·검토된 분류만 반영. 본문 `작업 구분`의 추정은 옮기지 않음 |
| 회신 상태 | 회신 불필요 / 회신 대기 / 답변 확인 중 / 회신 완료 | 요청자에게 답할 예정이거나 답이 필요하다고 하면 ‘답변 필요’ 계열 선택지. 언급이 없으면 비움 |
| 해결버전 | 확인된 배포 버전, 텍스트 | 새 티켓 생성에서는 비움 |
| 상태 | 실제 목록의 기본 상태 | 자동 실행을 유도하려고 다른 상태로 바꾸지 않음 |

## 실제 필드 매핑

1. 해당 목록에서 실제 필드 ID·유형·옵션과 작업 유형 적용 범위를 확인합니다. `플랫폼`과 `제품`, `답변 여부`와 `회신 상태`처럼 이름이 달라도 위 의미에 맞으면 매핑합니다.
2. 같은 이름의 칸이 여러 개면 같은 값을 넣을 수 있는 칸에 모두 넣고 표에 그렇게 적습니다. 위 의미 어느 것과도 맞지 않는 칸은 비웁니다.
3. 드롭다운·사람·날짜·복수 선택 값은 현재 커넥터가 요구하는 형식을 따릅니다. 화면의 순번·이름을 ID라고 가정하지 않습니다.
4. 표준안의 선택지가 실제로 없으면 자동 생성·수정하지 않습니다. `미확인`도 실제로 존재하는 선택지일 때만 저장합니다.
5. 단일 선택 필드에 제품·기관이 여러 개면 임의로 하나만 남기지 않습니다. 복수 선택 불가를 알리고 전체 값을 본문에 보존합니다. 실제 필수 필드라면 대표값 선택을 확인받습니다.
6. 실제 필수 필드가 누락됐으면 등록 전 필요한 값만 확인합니다. 생성 API가 허용하더라도 필수 의미를 빈 기본값으로 우회하지 않습니다.
7. 표준안에만 있고 목록에 없는 칸(환경·업무 영역·요청자 등)은 표에 넣지 않고 값을 본문 1절에 보존합니다. 선택지가 없으면 `미적용: 선택지 없음`, 권한·기능이 없으면 그 사유를 표시합니다.
8. 설정 후에는 실제 저장값을 비교합니다. 성공 응답만 보고 지원하지 않는 컬럼까지 적용됐다고 보고하지 않습니다.
9. 표에는 값마다 근거를 적습니다. `입력`은 사용자가 말한 값, `판단`은 화면·문맥으로 고른 값, `작성일`은 날짜가 없어 오늘로 채운 값입니다. 판단한 값은 확인 단계에서 고칠 수 있게 보여 줍니다.

## 조회 범위

- 처음에는 해당 목록·필드만 확인합니다. 같은 대화에서 확인한 ID와 매핑은 재사용합니다.
- 반환 결과를 제어할 수 있으면 ID·이름·유형·옵션·필수 여부·적용 범위 등 필요한 정보만 요청합니다.
- 권한 오류·필드 변경이 확인되면 관련 설정만 갱신합니다. 다른 목록으로 우회하지 않습니다.
- 스킬은 컬럼 신설·이름 변경·삭제, 기존 티켓 일괄 수정, pipeline 설정 변경을 수행하지 않습니다.
