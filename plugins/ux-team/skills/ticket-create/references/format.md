# 티켓 제목·본문 양식

입력 방식은 자유롭게 두고, 결과를 아래 구조로 정리합니다.
날짜·기관·요청자·제품·버전은 컬럼에 두고, 설명이 필요한 조건은 본문에 적습니다.
실제 컬럼에 저장할 수 없는 정보는 본문에 보존합니다.

## 제목

```text
[화면·기능명] 발생 조건 + 현상 또는 변경 요청
```

- 문제나 변경 목적 하나를 요약합니다. 30~60자 정도를 권장하되 조건을 없애면서 줄이지 않습니다.
- 전체 메뉴 경로·요청자·접수 날짜는 제목에 나열하지 않습니다.
- 오류: 현재 관찰한 동작을 씁니다. 예: `[재원생 추가] 새로 추가 선택 시 기존 선택 목록이 유지됨`.
- 개선: 원하는 변경을 씁니다. 예: `[미납 관리] 수납 관리 버튼명을 수납 생성 및 알림 발송으로 변경`.
- 오류인지 개선인지 불분명하면 정책을 지어내 분류하지 말고 초안의 유형을 `미확인`으로 둡니다.

## 본문

목록에 걸린 수동 작성 양식과 같은 소제목·항목 이름·순서를 씁니다. 사람이 쓴 티켓과 스킬이 쓴 티켓을 같은 자리에서 읽게 하려는 것입니다.
하위 항목은 필요한 것만 채우고, 최소 정보가 없으면 `미확인`으로 표시합니다.
기기·OS·브라우저는 증상 확인에 필요할 때 적고, 관계없다면 생략합니다.
수동 양식의 `※` 안내 줄과 `❗ 필수` 표시는 작성자용 안내라서 옮기지 않습니다.

```markdown
**1. 화면 위치·발생 조건**
- 세부 화면 경로:
- 대상 및 발생 조건:
- 기기·OS·브라우저: 필요한 경우 작성
- 작업 구분: FE / BE / FE·BE / 미확인 (근거)

**2. 현재 현상·불편**
- 현재 현상:
- 업무상 불편 사항:
- 임시 해결 방법: 없음 / 미확인 / 방법 설명

**3. 재현·사용 순서**
1.
2.

**4. 기대 결과·완료 조건**
- 기대 결과:
- 완료 조건:
- [ ] 확인 가능한 기준

**5. 관련 자료·결정 필요 사항**
- 사진·영상: 무엇을 보여주는 자료인지 설명
- 관련 링크: 원문·디자인·관련 티켓 등
- 확인·결정 필요 사항: 없으면 ‘없음’
```

## 내용 작성 기준

| 항목 | 기준 |
|---|---|
| 화면 위치·발생 조건 | 정확한 경로·역할·대상 상태. 컬럼에 미적용된 제품·환경·기관 등도 여기에 보존 |
| 작업 구분 | 아래 ‘작업 구분’ 기준으로만 적고 괄호에 근거를 붙임 |
| 현재 현상·불편 | 직접 재현 / 요청자 보고 / 이미지 관찰을 구분. 범위·금액·빈도는 제공된 것만 사용 |
| 재현·사용 순서 | 오류는 알려진 재현 순서, 개선은 현재 사용 순서. 재현하지 못했다면 그 사실을 표시 |
| 기대 결과·완료 조건 | 실제 확인할 수 있는 결과. 기대 결과가 없으면 ‘미확인’으로 두고 완료 조건을 만들지 않음 |
| 관련 자료·결정 필요 사항 | 자료 설명, 근거 링크, 아직 정하지 않은 정책. 제안은 제안이라고 표시 |

- `정상 동작`, `편하게 개선`처럼 확인 방법이 없는 표현은 구체적인 관찰 결과로 바꿀 수 있는지 봅니다. 새 결과를 임의로 보태지는 않습니다.
- 관련 없는 예외·화면·기능을 완료 조건에 추가하지 않습니다.
- 암호·인증 토큰은 티켓에 옮기지 않습니다. 문제를 재현하는 데 필요한 대상 식별자는 팀의 접근 가능한 증거 링크로 최소한만 남깁니다.
- 요청 원문의 ‘있으면 좋겠다’는 의견을 승인된 정책이나 구현 결정으로 바꾸지 않습니다.

### 작업 구분

작업 구분은 개발 쪽이 티켓을 빨리 가르도록 남기는 첫 판단입니다. 처리 분류를 확정하지 않습니다.

- `FE (추정: …)`: 화면 안에서 끝나는 변경입니다. 표시·배치·문구·크기·색, 저장 결과가 그대로인 버튼·목록 동작이 해당됩니다.
- `BE (작성자 확인)` · `FE·BE (작성자 확인)`: 작성자나 개발자가 그렇다고 알려 준 경우에만 씁니다.
- `미확인`: 그 밖의 경우입니다. 저장·계산·발송·조회 결과가 틀리거나, 오류 코드·권한 문제처럼 화면만으로 가를 수 없으면 여기에 둡니다.

## 수동 접수의 최소 입력

수동 작성 양식에서 `❗ 필수`로 표시된 아래 항목으로 접수할 수 있습니다. 수동 작성자에게 나머지 항목이나 모든 컬럼 입력을 요구하지 않습니다.

```text
세부 화면 경로:
대상 및 발생 조건:
현재 현상:
업무상 불편 사항:
기대 결과:
사진·영상: 있으면 첨부
```

알고 있는 제품·환경·요청 기관은 선택하고 모르면 미확인으로 남깁니다.
긴급 건은 먼저 접수한 후 보완할 수 있습니다.
이 스킬은 제공된 입력을 정리합니다. 이미 수동 등록한 티켓을 자동 수정하거나 pipeline이 자동 보완한다고 안내하지 않습니다.
