# handoff-check

CRS-04 핸즈오프(기획자 → 개발) 직전에 기획 글과 아티팩트 · 프로토타입을 항목 단위로 대조합니다.
대조표, 미결 표시 건수, 기획자가 직접 확인할 질문을 냅니다.
넘길지 말지는 기획자가 정합니다. 이 스킬은 정하지 않습니다.

## 어디서 되는가

화면 판별은 `references/_shared/surfaces.md`를 따릅니다.

| 입력 | Chat | Cowork | Code 탭 |
|---|---|---|---|
| 기획 글 (요구사항 목록 · 정책 글) | 첨부 파일 · 붙여 넣은 글 | 연결한 폴더의 파일도 | 로컬 파일도 |
| 아티팩트 링크 | 읽히면 읽습니다. 못 읽으면 HTML 첨부를 요청하고 멈춥니다 | 같음 | 같음 |
| HTML · 프로토타입 파일 | 첨부 파일 | 연결한 폴더 | 로컬 파일 |
| world 브랜치 | 읽지 못합니다. 설명 · 캡처를 받습니다 | 레포 폴더를 연결했을 때만 코드를 읽습니다 | 레포를 열었을 때만 코드를 읽습니다 |

- 파일은 소스를 읽어 대조합니다. 브라우저로 띄워 누르지 않습니다.
- 브랜치는 체크아웃하지 않고 읽기만 합니다. 작업 트리를 바꾸지 않습니다.
- Figma 링크는 이번 판에서 입력으로 받지 않습니다. 받으면 "Figma 대조는 하지 않는다"고 알리고 나머지로 진행합니다.

## 하지 않는 것

- 기획 글이나 아티팩트를 고치지 않습니다. 미결 표시를 대신 달지도 않습니다.
- "확정", "통과", "넘겨도 됩니다"라고 쓰지 않습니다. 사람이 확인하기 전이기 때문입니다.
- ClickUp 서브태스크 상태나 브랜치 push 여부를 직접 보거나 바꾸지 않습니다. 했는지 묻기만 합니다.
- 근거 없는 판단을 채우지 않습니다. 모르는 것은 `미결`로 둡니다.

## 진행 순서

### 1. 입력 받기

- 기획 글과 아티팩트가 둘 다 있어야 시작합니다. 하나가 없으면 무엇이 빠졌는지 알리고 멈춥니다.
- 아티팩트 링크를 못 읽으면 "링크로 본문을 읽지 못했습니다. 아티팩트를 HTML 파일로 받아 첨부해 주세요."라고 요청하고 멈춥니다. 추측으로 대조하지 않습니다.
- 지금 화면에서 못 읽는 입력(Chat의 브랜치 등)은 건너뛰지 않고, 어디서 하면 읽히는지 알립니다.

### 2. 글을 항목으로 나누기

- ID가 있으면(`REQ-03` 등) 그 ID를 씁니다.
- ID가 없으면 불릿 · 표 행 하나를 한 항목으로 봅니다. 원문을 그대로 인용하고 위치(절 제목 · 몇 번째 줄)를 붙입니다.
- 에이전트가 새 ID를 만들어 붙이지 않습니다.

### 3. 아티팩트를 화면 요소로 나누기

- 단위는 화면(페이지 · 모달) › 영역 › 요소(버튼 · 필드 · 열 · 문구 · 상태 표시)입니다.
- 소스에서 화면 이름을 못 찾으면 보이는 제목이나 첫 문구로 부르고, 그렇게 불렀다고 적습니다.

### 4. 대조하기

- 글 항목 하나를 6축(있음 · 문구 · 조건 · 값 · 예외 · 흐름)으로 나눠 봅니다. 축 정의와 예시는 `references/axes.md`를 대조 전에 읽습니다.
- 분류는 4종입니다.
  - 일치: 해당하는 축이 모두 같습니다.
  - 어긋남: 같은 요소를 가리키는데 축 하나 이상이 다릅니다.
  - 글에만 있음: 글 항목에 해당하는 요소가 아티팩트에 없습니다.
  - 아티팩트에만 있음: 글에 근거가 없는 요소입니다. 글에 적히지 않은 결정이므로 미결 후보로도 올립니다.
- 정적 파일로 볼 수 없는 축(대개 조건 · 예외 · 흐름)은 분류하지 않습니다. 대조표 밖 "확인 못 함" 절로 보냅니다.
- 보이는 축은 같고 못 본 축이 남은 항목은 "일치 (보이는 축만)"으로 적고, 못 본 축은 "확인 못 함"에도 올립니다. 그래서 두 건수는 겹칠 수 있고, 요약에 그렇게 밝힙니다.
- 소스로 동작을 추정할 수 있어도 판정하지 않습니다. 추정은 "참고"에만 적습니다.

### 5. 미결 세기

- 세는 표시와 0건일 때 낼 후보는 `references/axes.md`의 "미결 표시" 절을 따릅니다.
- 문서마다 건수와 위치를 적습니다.
- 0건이면 출력 맨 위에 다음 경고를 그대로 둡니다.
  - "미결 표시가 0건입니다. 처음 만드는 화면에서 모르는 것이 하나도 없을 수는 없습니다. 다시 봐 주세요."
- 경고 아래에 다시 볼 후보를 줍니다. 후보를 원문에 미결로 표시하지는 않습니다.

### 6. 사람에게 남길 질문 (CRS-04)

`references/_shared/crossings.md`의 CRS-04 "넘겨도 되는 조건"과 "남는 기록" 가운데 스킬이 볼 수 없는 것을 질문으로 남깁니다.

- 의도대로 동작하는지: 조건 · 흐름 축이 있는 항목마다 "프로토타입에서 직접 눌러 확인하셨나요?"를 항목 이름과 함께 묻습니다.
- 확인 못 함 항목: 무엇을 해 보면 되는지 함께 적습니다.
- 남는 기록: 서브태스크 "개발 전달" 완료와 브랜치 push를 했는지 묻습니다.

### 7. 출력

- 대화 본문에 마크다운으로 냅니다. 양식은 `references/output.md`를 출력 직전에 읽고 따릅니다.
- 파일로 남겨 달라고 하면 그때 저장합니다. 위치는 argument로 받고, 없으면 Cowork 연결 폴더나 Code 탭 현재 폴더, 그것도 없으면 묻습니다.
- 글은 `references/_shared/writing.md`를 따릅니다. 결론 → 판단할 것 → 확인할 것 → 참고 순서입니다.

## 이어지는 스킬

- 대조 중 막히거나 데이터 구조가 불확실하면 `call-lead`로 리드를 부를 수 있다고 알립니다.
- 기획자가 차이를 보고 무언가를 정했다면 `decision-log`로 남길 수 있다고 알립니다.
- 구현 뒤 staging 화면 확인은 `intent-check`가 맡습니다.
