# UX팀 플러그인 명세

UX팀 플러그인(`ux-team`)에 담을 스킬 12개의 정본 명세다.
트랙은 자기 스킬 절을 중심으로 읽되, 2절 결정과 3절 공통 전제는 모두 지킨다.

## 범례

| 접두어 | 원어 | 뜻 | 번호 |
|---|---|---|---|
| `DEC` | Decision | 정해진 결정 (누가 · 언제) | DEC-01부터 |
| `QST` | Question | 아직 정하지 않은 질문 | QST-01부터 |
| `RSK` | Risk | 확인이 필요한 위험 | RSK-01부터 |
| `ACC` | Acceptance Criteria | 스킬 완료 검증 항목 | ACC-01부터, 스킬을 넘어 이어서 |
| `CHG` | Change | 이식 트랙이 원본 대비 바꾸는 항목 | 트랙별 CHG 문서 안에서 CHG-01부터 |

- 한 번 붙인 번호는 바꾸지 않고, 뺀 번호는 비워 둔다.
- `CRS-NN`은 팀 파이프라인 문서의 교차 지점 번호다. 표는 `shared/crossings.md`에 있다.

## 1. 범위

- **담는 것:** 리드만 줄 수 있는 사내 맥락을 담은 스킬 12개 (4절)
- **담지 않는 것**
  - FE 전용 스킬: 레포를 열면 따라온다 (`requirement-list`, `lofi-to-plan` 등)
  - 리드의 릴리스 체인: `release-notes`, `user-manual`
  - 개인용: `slack-send`, `ledger` 등
  - 공개 스킬: 디자인 세트, `brainstorming` 등은 각자 공개 마켓플레이스에서 추가한다
  - `tring-policy`: 원본이 생기면 추가한다 (DEC-08)

## 3. 공통 전제

- **화면:** `shared/surfaces.md`의 판별과 분기 원칙을 따른다. 안 되는 단계는 건너뛰지 않고 알린다.
- **커넥터:** 도구 이름을 박지 않고 동작으로 쓴다. 예: "ClickUp 커넥터로 댓글을 단다". 연결이 없으면 Customize › Connectors를 안내하고 멈춘다.
- **쓰기 · 보내기:** 초안 → 사용자 확인 → 실행 순서를 지킨다. 확인 없이 만들거나 보내지 않는다.
- **결정 · 미결:** `shared/ux-team-guide.md`의 "결정은 사람이 한다"를 따른다.
- **출력 글:** `shared/writing.md`를 따른다.
- **비밀값 · 로그인:** 다루지 않는다. 로그인은 사용자가 직접 한다.

### hello-ux-team

| 항목 | 내용 |
|---|---|
| 종류 · 트랙 | 신규 · A |
| 켜짐 | 직접 (`disable-model-invocation: true`) |
| 화면 | Chat · Cowork · Code 탭 |
| 연결 | 없음 (커넥터는 연결 여부만 본다) |
| 공유 사본 | `ux-team-guide.md`, `crossings.md`, `surfaces.md` |

하는 일
1. 화면을 판별한다.
2. 팀 지침을 설치한다.
   - Code 탭: `~/.claude/rules/ux-team-guide.md`를 `references/_shared/ux-team-guide.md`로 통째로 덮어쓴다. 폴더가 없으면 만든다. 기존 파일과 다르면 바뀌는 내용을 먼저 보여 준다.
   - Chat · Cowork: 본문을 표시선 사이에 넣어 출력하고, 설정 › General › Instructions for Claude 맨 위에 붙여 넣으라고 안내한다. 갱신할 때는 표시선 사이만 바꾸라고 안내한다.
3. ClickUp · Slack 커넥터 연결을 보고, 빠진 것만 연결할 곳과 함께 알린다. Figma는 `screen-to-hifi`를 쓸 때만 필요하다고 알린다.
4. 스킬 목록 요약과 하네스 안내 문서 링크(https://claude.ai/artifact/A39pdxytvgJuhiac7Vw3ba)를 준다.

하지 않는 것: 개인 `~/.claude/CLAUDE.md`나 다른 파일을 고치지 않는다. 설정 화면을 직접 조작하지 않는다.

완료 기준
- ACC-01 Code 탭에서 두 번 실행해도 결과 파일이 같다.
- ACC-02 `~/.claude/rules/ux-team-guide.md` 밖의 파일을 바꾸지 않는다.
- ACC-03 Chat · Cowork에서는 붙여 넣을 본문, 위치, 표시선 안내만 출력한다.
- ACC-04 연결이 빠진 커넥터만 골라 어디서 연결하는지 알린다.
- ACC-05 사용자가 부르지 않으면 켜지지 않는다 (RSK-01 확인).

### tikita-policy

| 항목 | 내용 |
|---|---|
| 종류 · 트랙 | 자료 묶기 · E |
| 켜짐 | 자동 |
| 화면 | 모두 |
| 원본 | TIKITA WIKI 18쪽(`_개요.md`와 페이지 17개), 작업공간 지침의 "티키타 도메인 정책 참조" 절. 플러그인에는 사본을 담지 않고 조직 저장소에서 읽는다 (DEC-20, 저장소는 QST-10) |

지금 하는 일 (준비 중)
- 정책 위키가 연결되지 않았다고 알리고, 정책을 지어내지 않는다.
- 사용자가 붙여 넣은 자료가 있으면 그 안에서만 답한다. 없으면 미결로 남기고 물을 사람(리드)을 적는다.

하는 일 (위키 저장소가 연결된 뒤)
1. 먼저 위키의 `_개요.md`를 읽어 후보 페이지를 좁힌다.
2. 관련 페이지만 읽는다. 18쪽을 다 읽지 않는다.
3. 위키에서 답을 못 찾으면 지어내지 않고 미결 질문으로 남긴다.
4. 위키가 화면이나 코드와 다르면 위키를 따르되, 차이가 있다는 사실을 알린다. 위키가 최신이 아닐 수 있기 때문이다.
5. 답할 때 근거 페이지를 밝힌다.

정본 위치: 조직 저장소 (QST-10). 10/15에 리드 vault에서 복사해 담았던 사본과 `scripts/publish-wiki.sh`는 공개 전에 뺐다 (DEC-20).

완료 기준
- ACC-06 18쪽이 모두 `references/wiki/`에 있고, SKILL.md의 진입점이 `_개요.md`다. → 보류: 사본을 담지 않음 (DEC-20). 위키 저장소가 연결되면 다시 정한다.

- ACC-09 `publish-wiki.sh`를 다시 돌려도 결과가 같다. 정본 위치가 정해지면(QST-10) 이 기준을 다시 정한다. → 보류: 스크립트를 뺌 (DEC-20)
