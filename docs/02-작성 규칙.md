# 스킬 작성 규칙

모든 트랙이 지킨다.
기계로 볼 수 있는 것은 `python3 scripts/skills.py check`가 본다.
트랙 세션은 `check <자기 스킬>`로 자기 스킬만 본다. 전체 점검은 통합 단계에서 한다.

## 폴더와 frontmatter (check가 봄)
- 스킬 폴더는 `plugins/ux-team/skills/<이름>/SKILL.md`다. 폴더 이름이 곧 `name`이고, 소문자 · 숫자 · 하이픈만 쓴다.
- frontmatter는 리드 user scope 스킬과 같은 필드를 쓴다 (DEC-16). 뼈대에 채워 둔 값을 기준으로 삼는다.

```yaml
---
name: <폴더 이름>                     # my: 접두어 없이
version: 1.0.0
description: "<트리거 지도 문구>"       # 한 줄, 200자 이내
author: lee-changwook                  # 플러그인 스킬은 모두 같은 값
relates:                              # 이 플러그인 안의 스킬만. 없으면 relates: []
  - <스킬>
argument-hint: "<인자 힌트>"           # 인자를 받는 스킬만
triggers:                             # 자동 스킬만. description 안의 말만 쓴다
  keywords:
    - <대표 요청>
disable-model-invocation: false        # hello-ux-team만 true
---
```

- 필수 키: `name` · `version` · `description` · `author` · `relates` · `disable-model-invocation`
- 선택 키: `argument-hint` · `triggers` · `user-invocable` · `allowed-tools` · `metadata` · `license` · `tags` · `dependencies` · `hooks`
- `description`은 `docs/01-트리거 지도.md`의 문구를 그대로 옮긴다. 바꾸고 싶으면 보고서에 제안한다.

## 본문
- SKILL.md는 200줄 안팎으로 쓴다. 길어지는 내용은 `references/`로 빼고, SKILL.md에 그 파일을 언제 읽을지 적는다.
- 첫머리에 "어디서 되는가"를 적는다. `shared/surfaces.md` 기준으로 화면마다 되는 단계와 안 되는 단계를 나눈다.
- 커넥터는 도구 이름 대신 동작으로 쓴다. 연결이 없으면 안내하고 멈춘다.
- 쓰거나 보내는 동작은 초안 → 확인 → 실행 순서로 쓴다.
- 모르는 것은 미결로 남기라고 적는다. 에이전트가 정하지 않게 한다.
- 출력 글은 `shared/writing.md`를 따른다.
- 스크립트를 담으면 SKILL.md에 어느 화면에서 돌릴 수 있는지 함께 적는다.

## 금지 (check가 봄)
- 절대경로(`/Users/…`), 리드 계정명, `~/dada`, 리드 vault 경로
- 리드 개인 CLI: `clickup-cli`, `agent-slack`, `apidog`, `gh`
- 다른 스킬 폴더 참조(`~/.claude/skills/…`). 필요한 파일은 자기 폴더에 담는다.
- 비밀값과 계정 정보

## 공유 사본
- `references/_shared/`는 `sync`가 덮어쓴다. 직접 고치지 않는다.
- `shared/` 원본을 고쳐야 하면 보고서에 제안한다. `shared/`는 리드가 고친다.

## 원본 경로 바꾸기
원본 스킬의 고정 경로는 무엇을 가리키느냐에 따라 바꾼다. 모두 argument로 바꾸지 않는다.

| 경로가 가리키는 것 | 바꾸는 방법 |
|---|---|
| 스킬 자기 파일 (스크립트 · 템플릿) | 스킬 폴더 기준 상대경로. 스크립트는 자기 위치(`__file__`)에서 옆 파일을 찾는다 |
| 다른 스킬의 파일 | 자기 스킬 폴더에 복사해 담는다 |
| 출력 위치 | argument. 없으면 Cowork 연결 폴더나 Code 탭 현재 폴더, 그것도 없으면 묻는다 |
| 입력 · 대상 (URL, 파일) | argument나 첨부 파일. `argument-hint`에 적는다 |
| 정본 예시 문서 | 스킬 `references/`에 담는다. 실명이나 내부 자료가 든 문서는 담지 않거나 가상 예시로 바꾼다 |
| 실행 도구 (Chrome 앱 등) | 실행할 때 있는지 확인하고, 없거나 Code 탭이 아니면 다른 방법을 안내한다 |
| 리드 PC 상태 메모 | 경로 대신 현상만 설명으로 남긴다 |

- 플러그인은 두 기획자에게 배포된다. 실명과 내부 자료는 어떤 형태로도 담지 않는다.

## 이식 트랙
1. 원본을 자기 스킬 폴더로 복사한다. frontmatter는 뼈대에 채워 둔 값을 기준으로 두고, 원본에만 있는 키(`argument-hint` 등)를 더한다.
2. `check <자기 스킬>`을 돌려 리드 전용 흔적 목록을 뽑는다.
3. 원본 대비 바꿀 것을 `docs/tracks/<트랙>-CHG.md`에 CHG 목록(유지 · 삭제 · 변경 · 추가)으로 쓰고, 체크포인트에서 멈춘다.
4. 승인된 CHG만 적용한다.

## eval
- `docs/evals/<스킬>.md`에 켜져야 할 요청 5개, 켜지면 안 될 요청 5개, 기능 확인 3개 이상을 쓴다. 양식은 `docs/evals/_template.md`다.
- 켜지면 안 될 요청에는 트리거 지도에서 다른 스킬이 맡는 말을 넣는다.
