# ticket-create eval

## 검증 범위

- 아래 사례는 스킬·참고 자료를 대조하는 오프라인 시나리오 검토입니다. 실제 모델 실행이나 ClickUp 커넥터 통합 시험을 완료했다는 뜻이 아닙니다.
- 실존 기관·인물·티켓·운영 ID를 사용하지 않습니다. 외부 생성·수정·업로드·발송을 수행하지 않습니다.
- 패키지 검사·플러그인 검사·참조 무결성은 별도로 실제 실행해 기록합니다.

## 켜져야 할 요청

| 요청 | 의도한 동작 | 정적 검토 |
|---|---|---|
| 오류 티켓 만들어 줘. 출결 저장 버튼을 누르면 400이 떠요 | 표준 초안 생성. 원인·경로·환경은 근거가 없으면 미확인. 게시 전 확인 | 지침 부합 |
| 개선사항 등록해 줘. 목록의 선택 해제를 한 번에 하고 싶어요 | 개선 초안과 등록 대상·필드 확인. 확인된 요구 범위만 완료 기준에 포함 | 지침 부합 |
| 이 이미지로 티켓 초안만 작성해 줘 | 이미지를 읽을 수 있는지 확인. 관찰한 내용만 작성. 커넥터 조회·등록 없음 | 지침 부합 |
| 이 메모와 첨부 파일로 오류 티켓 초안만 작성해 줘 | 읽을 수 있는 파일만 근거로 사용. 모르는 값은 미확인. 등록 없음 | 지침 부합 |
| 오류·개선 티켓을 두 건 만들어 줘. 내용은 각각 … | 독립 초안 두 건. 등록 목록·개수·첨부를 함께 확인 | 지침 부합 |

## 실제 통합 시험에서 남은 것

- 각 사용자의 Chat·Cowork·Code에서 스킬 발견·입력 파일 접근·커넥터 연결 확인.
- 지정한 시험 목록에서 생성·필드 설정·첨부·저장값 읽기와 일부 실패 처리 확인.
- 컬럼 신설 전후의 매핑, 실제 필수 필드와 작업 유형 적용 범위 확인.
- 대표 티켓 몇 건의 작성 시간·추가 질문 횟수·도구 호출·가능한 사용량 지표 기록. 토큰 절감률·작성 시간 단축은 실측 전 단정하지 않음.
