# artifact-style eval

## 켜져야 할 요청
1. 이번 주 회의에서 정할 것 정리해서 팀이 볼 아티팩트로 만들어 줘.
2. 프로젝트 진행 현황을 HTML 페이지로 만들어 줘. 창욱님 · 유진님 · 주은님이 볼 거야.
3. 이 아티팩트 다크 모드에서 색이 이상해. 팀 토큰으로 맞춰 줘.
4. 새로 온 사람용 팀 안내를 HTML 페이지로 만들어 줘.
5. 이 HTML 페이지 올리기 전에 줄바꿈이랑 버전 라벨 점검해 줘.

## 켜지면 안 될 요청
다른 스킬이 맡는 말을 넣는다 (`docs/01-트리거 지도.md`의 "겹치는 말 정리").

| 요청 | 대신 맡는 스킬 |
|---|---|
| 인터뷰 메모로 팀에 공유할 리포트 HTML 만들어 줘 | `research-report` |
| 출결 관리 새 기능 사용 설명서 PDF 만들어 줘. 학원에 보낼 거야 | `feature-guide` |
| 이 staging 화면 피그마로 떠서 시안 얹어 줘 | `screen-to-hifi` |
| 넘기기 전에 이 아티팩트랑 요구사항 글이 맞는지 확인해 줘 | `handoff-check` |
| staging에 올라간 화면이 의도대로 됐는지 봐 줘 | `intent-check` |

## 시험 기록
스킬 폴더만 따르게 한 서브에이전트(opus, Code 탭)에게 켜져야 할 요청 1과 같은 회의 안건 페이지를 만들게 했다.

- 결과: 머리(무엇을 정하는지) → 판단할 것 → 확인할 것 → 참고 → 꼬리 순서. 근거 없는 칸은 `미결`, 경고는 점선 + "섞임" 라벨.
- `preflight.py`: 고칠 것 0건. 확인할 것 2건은 위키 절 번호 "D."를 문장 끝으로 본 오탐이었다.
- 캡처: 라이트 1280px, 다크, 390px 라이트 · 다크 나란히. 페이지는 넘치지 않고 표만 감싸개 안에서 스크롤된다.

시험 뒤 고친 것
- `preflight.py`: "D." "3." "A-1." 같은 절 번호 뒤 마침표는 문장 끝으로 보지 않는다. 다시 돌려 확인할 것 0건.
- `components.md`: 예시 문구를 `<…>` 자리 표시로 바꿨다 (예시를 베껴 쓰지 않게). `미결` 칩, `.owner`(안건 카드의 담당자 이름), 머리 카드 안 불릿, 표 감싸개 초점 테두리를 더했다. 경고 라벨 예시에 "섞임" · "중복"을 더하고, 열이 적은 표는 최소 폭을 줄이라고 적었다.
- `SKILL.md`: 결론이 아직 없는 문서는 "무엇을 언제까지 정하는지"를 결론 자리에 둔다. 날짜는 요일과 함께 쓴다. 티키타 정책 · 용어는 `tikita-policy`로 찾고 못 찾으면 `미결`.
- 원래 문서 두 편에 다시 돌렸을 때 줄바꿈 오탐 0건 (토큰 · 색값은 옛 색이라 잡히는 것이 맞다).

시험 범위 밖
- 시험 에이전트가 위키를 스킬 폴더가 아닌 리드 PC의 원본에서 읽었다. 팀원 화면에서는 `tikita-policy`가 켜져야 같은 일이 된다. 두 스킬이 함께 켜지는지는 통합 단계에서 본다.
