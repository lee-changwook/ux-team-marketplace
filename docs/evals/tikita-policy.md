# tikita-policy eval

## 켜져야 할 요청
1. 출결 상태에서 지각과 결석은 어떻게 달라?
2. 청구랑 수납이 왜 1:1이 아닌지, 부분 청구 · 부분 결제가 왜 있는지 정책 기준으로 알려 줘.
3. 이 기획서에 재원생 · 수강생 용어가 맞게 쓰였는지 봐 줘.
4. '출결 관리' 화면 정책 글을 쓰는데 예정 · 확인 · 확정 · 신청 조합을 정리해 줘.
5. 납입 취소랑 환불은 결제 쪽에서 어떻게 달라?

## 켜지면 안 될 요청
다른 스킬이 맡는 말을 넣는다 (`docs/01-트리거 지도.md`의 "겹치는 말 정리").
일부러 도메인 용어(출결 · 청구 · 결제)를 섞었다. 맡는 스킬이 먼저 켜져야 하고, 그 스킬이 정책 확인을 위해 이 스킬을 함께 쓰는 것은 괜찮다.

| 요청 | 대신 맡는 스킬 |
|---|---|
| 원장님 세 분 출결 앱 인터뷰 메모야. 정리해서 리포트로 만들어 줘 | `research-report` |
| 결제 내역 화면 사용 설명서 PDF 만들어 줘. 원장님들한테 보낼 거야 | `feature-guide` |
| staging의 출결 관리 화면이 의도대로 구현됐는지 봐 줘 | `intent-check` |
| 넘기기 전에 청구 기획서랑 프로토타입이 맞는지 확인해 줘 | `handoff-check` |
| 이거 결정됐어: 보강은 출결 상태가 아니라 별도 처리로 둔다. 기록 남겨 줘 | `decision-log` |

## 시험 기록 (위키 사본판)
스킬 폴더만 읽게 한 서브에이전트(opus)에게 위 세 질문을 물었다.

| 질문 | 읽은 파일 | 답 요지 |
|---|---|---|
| 지각과 결석 | SKILL.md → `_개요.md` → `pages.md`. 06쪽은 "비어 있음"이라 열지 않음 | `_개요.md` D-4 원문 두 줄을 인용해 "참여 여부"로 가름. 지각 기준 시간 등은 미결, 06쪽이 비어 있다고 알림 |
| 미납 독촉 자동 발송 | 위와 같음 + `00.전체 처리.md`를 찾는 말로 훑음 | 미결. 독촉 기준은 `04.미납 관리`, 발송 방식은 `08` · `10`번 쪽에 있어야 하나 모두 비어 있다고 적고, 물을 사람은 리드 |
| 기획서 두 문장 검토 | `_개요.md` | 재원생 · 수강생 정의가 바뀐 것과 청구 : 수납 = 1 : N을 줄마다 원문 근거로 짚음. N:N 해석은 "확정 아님"으로 나눠 적음 |

시험 뒤 고친 것 (시험 에이전트가 따르기 어렵다고 한 점)
- "읽는 순서": `_개요.md`와 `pages.md`를 함께 열어도 된다고 적고, 긴 쪽은 찾는 말로 훑어도 되며 훑기만 했으면 그렇게 적으라고 더했다.
- "어디를 볼지": 미납 · 독촉, 재원생 목록 · 등록 · 재원 신청 · 결제 내역, 표에 없는 질문 줄을 더했다.
- "답하는 방법": 답의 모양에 "해석" 칸을 더하고, 검토 답은 줄마다 근거를 붙이게 했다.
- "위키 안에서 서로 다를 때" 절을 더했다. 시험 중 `_개요.md`의 "재원생" 정의(A. 대상 2번)와 3번 아래의 "재원생 - 현재 수강 중인 수업이 있음"이 두 가지로 읽힌다는 점이 나왔다.
