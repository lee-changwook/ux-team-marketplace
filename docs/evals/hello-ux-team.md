# hello-ux-team eval

직접 호출 전용 스킬이다(DEC-05).
그래서 "켜져야 할 요청"은 사용자가 이름으로 부르는 경우만 두고, "켜지면 안 될 요청"에는 부르지 않고 말로만 한 요청(ACC-05)과 다른 스킬이 맡는 말을 함께 넣는다.
ACC · DEC · RSK 번호는 `docs/00-명세.md`의 것이다.

## 켜져야 할 요청
1. Code 탭에서 `/ux-team:hello-ux-team`
2. Code 탭에서 `/hello-ux-team` (짧은 이름을 쓰는 다른 명령이 없을 때)
3. Chat에서 `/hello-ux-team`
4. Cowork에서 `/hello-ux-team`
5. `/hello-ux-team 리드가 팀 지침 갱신했대` (인자를 붙여 불러도 같은 흐름)

## 켜지면 안 될 요청
다른 스킬이 맡는 말을 넣는다 (`docs/01-트리거 지도.md`의 "겹치는 말 정리").

| 요청 | 대신 맡는 스킬 |
|---|---|
| UX팀 지침 설치해 줘 (슬래시 없이) | 없음. 스킬이 켜지지 않고, `/hello-ux-team`을 직접 실행하라고 안내한다 (ACC-05) |
| 리드가 팀 지침 바뀌었대, 반영해 줘 | 없음. 위와 같다 (ACC-05) |
| 프로젝트 배정됐어, 상위 태스크 만들어 줘 | `kickoff` |
| 넘기기 전에 확인해 줘 | `handoff-check` |
| 막혔어, 창욱님 불러 줘 | `call-lead` |

## 기능 확인
| 확인 | 화면 | 기대 결과 | 관련 ACC |
|---|---|---|---|
| 처음 실행 → 같은 화면에서 한 번 더 실행 | Code 탭 | 첫 실행은 `NEW` → 묻지 않고 설치, 두 번째는 `SAME` → 아무것도 쓰지 않음. 두 번의 결과 파일 해시가 같다 | ACC-01 |
| 실행 전후 파일 비교 | Code 탭 | 바뀐 것은 `~/.claude/rules/ux-team-guide.md`와 처음 만든 `rules/` 폴더뿐이다. 백업 · 임시 파일이 없다. 대상이 링크면 덮어쓰지 않고(`LINK`) 링크 너머 파일도 그대로다 | ACC-02 |
| 설치된 파일과 새 지침이 다를 때 | Code 탭 | 바뀌는 절 요약과 diff를 보여 주고 "덮어쓸까요?"라고 묻는다. 답하기 전에는 `apply`를 돌리지 않는다. 승인하면 원본과 바이트가 같아지고, 거절하면 그대로다 | ACC-01 · ACC-02 |
| macOS가 아닌 셸에 `~/.claude`가 있을 때 | Cowork 격리 환경 | `check`가 `NOT_MAC`을 내고 붙여 넣기 흐름으로 간다. 파일을 쓰지 않는다 | ACC-02 · ACC-03 |
| 붙여 넣을 글 출력 | Chat · Cowork | 양식(붙여 넣는 위치, 탭 분리 화면 한 줄, 표시선 두 줄, 갱신 방법)만 나온다. 표시선 사이 글이 `references/_shared/ux-team-guide.md`와 한 글자도 다르지 않다 | ACC-03 |
| Slack만 로그인 안 된 상태 | 모두 | 표에 Slack(로그인 필요)만 나오고, 연결된 ClickUp은 나오지 않는다. 커넥터 도구 호출이 0건이다 | ACC-04 |
| Figma가 없는 상태 | 모두 | Figma 줄에 "`screen-to-hifi`를 쓸 때만 필요합니다"가 붙는다. Figma가 연결돼 있으면 언급하지 않는다 | ACC-04 |
| 이름을 부르지 않고 관련 요청만 함 | 모두 | 스킬이 켜지지 않는다. `/` 목록에는 보인다 | ACC-05 (RSK-01) |

## 시험 결과 (10/15, 트랙 A)

리드 PC의 `~/.claude/`에는 쓰지 않았다. `scripts/install-guide.sh`의 대상 경로 인자를 세션 임시 폴더로 바꿔 돌렸다.

| 시험 | 결과 |
|---|---|
| `check` → `apply` → `check` → `apply` | `NEW` → `INSTALLED` → `SAME` → `SAME`. 두 번의 SHA-256이 같고 원본과 바이트가 같다 (ACC-01) |
| 임시 폴더 안 파일 목록 | 첫 `apply` 뒤와 두 번째 `apply` 뒤가 같다. `rules/ux-team-guide.md`와 상위 폴더만 있다 (ACC-02) |
| 설치된 파일 한 줄을 고친 뒤 `check` | `DIFF`와 이름표("지금 설치된 지침" · "새 지침")가 붙은 diff가 나온다. `apply` 뒤 원본과 같아진다 |
| 대상이 다른 파일을 가리키는 링크 | `check` · `apply` 모두 `LINK`, `apply` 종료 코드 1. 링크 너머 파일 내용이 그대로다 (ACC-02) |
| 가짜 `uname`(Linux)으로 실행 | `check` · `apply` 모두 `NOT_MAC`, 대상 폴더를 만들지 않는다 |
| 인자 없이 실행 | 사용법을 출력하고 종료 코드 2 |
| 리드 PC의 실제 `~/.claude/rules/` | 시험 전후 모두 없음 (변화 없음) |

통합 단계에서 확인할 것
- 스킬 단위(에이전트가 SKILL.md를 따라 움직이는지) 시험은 플러그인을 실제로 켠 화면에서 한다. 위 표는 설치 스크립트 단위 결과다.
- 플러그인 스킬에서 `${CLAUDE_SKILL_DIR}`가 풀리는지, `allowed-tools` 허용으로 권한 창이 뜨지 않는지 (Code 탭).
- Chat · Cowork 출력의 표시선 사이 글을 복사해 원본과 대조한다.
- `/` 목록에 보이는지와 이름을 부르지 않으면 켜지지 않는지 (RSK-01, ACC-05).
