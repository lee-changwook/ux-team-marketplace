# 교차 지점

CRS-NN은 팀 파이프라인 문서의 교차 지점 번호다: https://claude.ai/artifact/1sbYWBaa5a4LiXaYjVRKhk
한 번 붙인 번호는 바꾸지 않는다. CRS-01은 창욱 노선의 BE 계약 확인으로 옮겨 비어 있다.

| 지점 | 누가 → 누구 | 넘기는 것 | 넘겨도 되는 조건 | 남는 기록 | 상태 | 스킬 |
|---|---|---|---|---|---|---|
| 입구 | 전사 미팅 → 담당 기획자 | 프로젝트 배정 | 팀 스페이스에 상위 태스크로 등록함 | 상위 태스크 생성 시각 (리드타임 시작) | 10/13 합의 | `kickoff` |
| CRS-02 교차 리뷰 | 주은 ↔ 유진 | 정책 글, 예외 목록 | 미결 항목이 표시돼 있음 | 서브태스크 "리뷰 반영" 완료 | 제안 | — |
| CRS-03 중간 확인 | 주은 · 유진 → 창욱 | 구현 중인 world 브랜치 | 막힌 지점이나 불확실한 데이터 구조를 적어 부름 | 상위 태스크 댓글 | 10/13 논의 | `call-lead` |
| CRS-04 핸즈오프 | 기획자 → 창욱 | 동작하는 프로토타입(브랜치나 아티팩트), 글 | 기획 의도대로 동작하는지 기획자가 확인함, 글과 아티팩트가 일치함 | 서브태스크 "개발 전달" 완료, 브랜치 push | 10/13 합의 | `handoff-check` |
| CRS-05 QA · 최종 확인 | 창욱 → 기획자 · 팀 | staging 화면 | 에이전트 QA 통과, 실결제 확인, 기획 의도 확인 | PR merge | 10/13 합의 | `intent-check` |
| CRS-06 피드백 | 현장 → 기획자 | CS, 유저 보이스 | 재기획이면 원래 상위 태스크에 연결 | 재기획 티켓 (재기획률), 제품 데이터 (완주율) | 10/13 논의 | `research-report` |
| CRS-07 티켓 질문 | 창욱 → 티켓 생성자 | 기획 판단이 필요한 질문 | 티켓 댓글에서 생성자를 @멘션, 답도 같은 티켓에 | 티켓 댓글 | 제안 | — |
| 중앙 컨텍스트 | 세 노선 모두 | 용어 사전, 코어 구조, 상충, 결정 기록 | 기준은 staging · prod와 맞는 최신 기획서 | ClickUp 팀 태스크 | 10/13 합의 | `decision-log` |

- 상태가 "제안"이나 "논의"인 지점은 팀이 합의하면 이 표를 고친다.
- 스킬은 지점의 형식을 대신 지켜 주는 도구다. 넘길지 말지는 사람이 정한다.
